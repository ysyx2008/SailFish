# Spec 驱动开发

模块 `SPEC.md` / `*_SPEC.md` 记录用户确认的需求、取舍和行为承诺，优先写设计目标：问题、成功标准、关键取舍和明确不做的事；其次写外部行为、不变量与边界。

用用户能理解和验收的语言，不从代码反推需求，不写内部类名、函数步骤或文件清单。公开 API、配置、协议字段、错误码作为契约时可精确命名并描述兼容性。

- 动手前读 SPEC；新模块先有设计目标，再实现、补行为契约。
- 确认的新设计先写 SPEC；实现要偏离时先对齐并更新。普通实现调整不机械同步 SPEC。
- 缺少用户共识时标「待对齐」，不编造目标。长度按设计复杂度决定。

实现方案放 `docs/plans/YYYY-MM-DD-<主题>-design.md`，文首写日期；大方案列任务拆解和逐步验收。完成后文件加 `done-` 前缀、文首标已完成，持久取舍归入 SPEC；暂缓标「未完成（暂缓）」而不加 done。保留历史，不让过期 Plan 覆盖当前契约。源码、测试和开发指南可解释实现。
