# 控制面板（设置）

## 设计目标

### 为什么需要这份规范

控制面板有二十多个页面，长期以来各写各的。同一个「卡片」在不同页面里其实是不同的东西，同一个开关有三套互不相干的实现，圆角用过十四种取值、字号用过二十一种。结果有两个：

一是页面之间对不上，用户在设置里连着切两页，会觉得像进了两个软件，业余感就是从这儿来的。

二是任何想统一的努力都会误伤。因为没有共同词汇，一条「给所有卡片加边框」的规则会自动伸手够到那些结构完全不同的页面——有的页面内部本来就套着带边框的盒子，外面再加一圈就成了套娃；有的页面开关是自制的，被同名规则一撞就散架。这两种事都真实发生过。

所以问题不是「有几页没调好」，是**根本没有一套大家共用的基础件**。

### 成功标准

- 用户在设置面板里连续切换任意两页，感觉是同一个软件里的同一个地方
- 同一类东西——卡片、设置行、分组标题、开关、分段选择、页内标签条、表单字段——在所有页面里长得一样、行为一样、间距一样
- 新增一个设置页时，作者不需要、也不应该重新设计这些东西；照着现成的拼即可
- 任何一次统一性改动，都不会让没被改造的页面出问题

### 关键取舍

**基础件是加入制，不是覆盖制。** 一个页面只有在被明确改造时才采用新样式；没改造的页面一行都不会动。宁可让统一来得慢一些，也不接受「改一处、坏一片」。这条是从实际教训里来的，不是洁癖。

**基础件要约束结构，不能只约束外观。** 光有一套样式规范拦不住页面往设置行里塞一个自带边框的盒子，也拦不住有人另起一套开关。所以基础件必须限定里面能放什么，而不是只规定看起来什么样。

**尺寸只能从固定档位里取。** 间距、字号、圆角各自只保留有限几档。如果某处取不到合适的值，那说明设计意图没想清楚，而不是应该新增一档。

**不追求一次推平。** 先把基础件立住、做出样板页，其余页面逐步迁移。中途停下也不倒退——基础件在那儿，此后新写的页面自然就是规范的。

**密钥有统一的输入框，密码不在其内。** API Key、Secret、Token 这类密钥，在面板里用同一种输入框，长得一样、行为一样：
- 平时遮住，只露开头 3 位和末尾 4 位，中间固定 8 个圆点——圆点个数不随密钥长短变，太短的密钥一位都不露。
- 右侧有显示/隐藏按钮，点开看全文。
- 点进去想改时，框里临时换成可编辑的真实内容（一个字符一个圆点），点到别处再遮回去。输入框只能显示它自己的内容，所以要在不编辑的时候才能换一种显示。
- 点进去的那一下把内容全选：遮盖的文字和真实内容长短不同，点在哪儿都对不上眼前的字，满屏圆点里插错了位置也看不出来。全选后直接粘贴新密钥就是替换；只想改其中几位，再点一下定位。已经点开眼睛看着全文时不全选，点哪儿光标就在哪儿。
- 「留空」本身有含义的框（比如搜索默认沿用模型的密钥），保持留空，只把正在用的那一把显示在框里，样子和用户自己填的一样。

账号密码、私钥口令不是密钥，不适用这条，仍是普通密码框。迁移按「不追求一次推平」逐页进行：换上的页面看起来一致，没换的保持原样。

**页名有固定位置，不许分组顶包。** 每一页都要有明确的页头：页名、一句说明、以及属于整页的操作入口。此前面板没有这一层，于是各页都拿第一个分组的标题当页名使——那个标题于是既不是页名（侧栏已经写了，重复）也不是分组名（它下面还有别的分组没标题）。同一个错误在不同页面发作，表面看像是「每页各有各的风格」，其实是同一个洞。

**每个分组都要有标题。** 一页之内不允许有的分组带标题、有的不带；缺标题的那块会从页面节奏里掉出来。如果某一组实在想不出名字，说明它要么不该独立成组，要么和相邻的组本就是一回事。

**边框颜色只表示「这是当前生效的那一个」。** 连接与否、运行与否这类状态一律用状态点加文字表达，不借边框颜色。理由有二：同一个视觉信号不能在 A 页表示「选中」、在 B 页表示「已连接」；状态往往不止两种（还有连接中、失败），边框颜色分不过来，而状态点可以。

**一块内容只由一层盒子承载。** 如果里面的东西自己就是一张张卡片或自带边框的盒子，那么外面那一层就不该存在——它不提供任何信息，只多出一圈边界。这是面板里犯得最多、也最伤观感的错：曾出现过一处套三层框，也出现过两层样式完全相同、纯属白套的盒子。判断方法很简单：把外层去掉，如果读者理解这块内容不受影响，那它本来就是多余的。

**同一件事只说一遍。** 同一个事实不允许在面板里有第二处说法。两处一旦并存就会各自演化，日后必然对不上，而对不上那天没人会收到通知——真实发生过：某个平台的配置步骤在页面里存了简版与详版两份，简版少了三步必需操作，照着做根本连不上。页名与侧栏名同理，取同一个来源。

**动作和设置项是同一种东西。** 「打开日志目录」这类动作，与「是否开机自启」这类开关，在面板里长一个样：左边说明这是什么、右边是操作它的控件，只不过一个右边是按钮、一个右边是开关。不为动作另立一种「按钮区」形态——那正是各页发明出一堆同义容器的由来。相应地，行的名字应当是**名词**（这是什么），按钮上才是**动词**（对它做什么），不要让两处重复同一句话。

**动作要交代什么场合用它，但只交代一遍。** 「复制崩溃摘要」这类动作，名字说清了它做什么，却容易漏掉用户什么时候该做——曾经漏到产品作者自己看着都想不起这按钮有什么用。所以只在特定处境下才用得上的动作，说明里必须带上处境。**但场合要就近说在动作自己的说明里，不为它另加一段组说明**：一行的说明已经写着「可直接粘贴发给我们」，组说明再讲一遍「反馈问题时从这里取资料」，就是同一件事说了两遍。

**只读的现状信息单独成一类。** 「上次异常退出过」「已连接三台」这种句子既不是设置项也不是动作，用户读完可能要去别处做事，但这一条本身不可操作。它需要自己的固定形态，不要临时拿一段带背景色的文字凑。默认不上颜色；上了颜色就得说得出具体后果，否则按前条规矩它本就不该写。

**开与关只有一种画法。** 同一个「开 / 关」，面板里曾经既有开关也有勾选框，数量还是勾选框占多数。这不是两种控件的分工，是同一件事有两个说法。规矩是：单个开关一律用开关；只有从一堆东西里挑出若干项（多选）才用勾选框。互斥单选同理——一律用摊开的档位或下拉，不用单选按钮组。

**一页只装一件事；装不下就该是两页，不是加一条标签条。** 判断标准是：两块内容如果各自都有自己的长列表、自己的保存动作，那它们本来就是两页，该在侧栏各占一条。「安全与权限」曾经把「哪些命令算危险」和「各级危险怎么处理」挤在一页靠标签条切换，两块还各带一个保存按钮存同一份东西——这时候换什么控件都不会好，因为问题不在控件。侧栏分组宁可多一组，也不要让一页装两页的内容。

**真需要页内分块时，用固定的标签条，并且它得看着像导航。** 有些页面的两块内容是「同一批东西换个看法」（如「我的技能 / 技能市场」），那才该留在一页。这时不许各页自己发明标签条，也不许借用档位切换的控件来充数：档位切换说的是「这个设置的取值是它」，标签条说的是「你正在看这一块」——一个取值，一个导航，画成一样用户会把块名当成某个设置项选中的值。标签条与侧栏同属导航语言：只有文字和一道标示当前位置的线，不占强调色块。

**分组标题只用文字，不配图标。** 曾有页面给每个分组标题配了图标，全面板仅此一页。图标要么所有页都有，要么都没有；而「外观」「行为」这类分组本就抽象，硬配图标只会让图标不再表意。

**侧栏分组按事情分，不按去的次数。** 「常用 / 其他」是按点开频率切的，和旁边按主题分的组不是一把尺子，其他组也容易变成抽屉。侧栏五组各自回答一件事：软件长什么样、怎么操作（偏好）；模型与记忆（AI）；跟外面怎么连（集成）；动手时谁说了算（安全）；这台安装本身（系统：数据在哪、坏了怎么取证、现在是哪个版本）。「关于」放在系统组最后。

**「关于」是唯一一页不按设置页排布的页。** 它不是设置项的集合，而是软件的身份与版本状态，所以按品牌页排布（居中的标识、版本号、更新入口与链接）。把它写成明文例外而不是让它「碰巧不一样」，是为了让规矩仍然只有一条：除这一页外，所有页一律按设置页排布。它仍受同一宽度与外边距约束，切过去不会觉得换了个软件。

**要求显式保存的页，切走之前必须问一声。** 面板里绝大多数设置改完即存，但少数危险设置（如各风险级别的处置）刻意保留「刻意提交」这一步。这类页原先只在自己内部的切换处拦一道，从侧栏点走则无声丢弃——被保护的恰好是最不可能的那条出口。凡是有未保存改动的页面，从任何出口离开都要先问，且问法在全面板一致。

**同一份设置被两页分管时，各页的「恢复默认」只能动自己管的那部分。** 否则用户在 A 页点一下恢复默认，B 页里配好的东西会不声不响地消失——他既不会想到去看，也不会收到任何提示。

**说明就近出现，不常驻铺开。** 「怎么拿到这个凭证」「这一步在对方后台怎么点」这类内容，只在用户正做那件事时才有意义。把所有情况的说明一次性铺在页面上，得到的是一堵与当前操作无关的文字墙——排版怎么调都不会好看，因为那些内容本来就不该同时出现。它们应当收在需要时才打开的地方，且不打断用户手上的操作。

**不常用的放到下面。** 一页里先放进来就要看、就要用的（正在管的列表、正在做的事），改完就很少再碰的设置沉到底。冷设置顶在第一屏，挡的是正事。判断看「是不是几乎每次打开都要动」，不是看它重不重要——记忆有多长、文档怎么入库，重要，但几乎没人天天改。

操作和设置长得一样：左边是名词，右边是动作按钮。不要再堆一排会换行的按钮。

会整份毁掉、又恢复不了的动作，按钮必须一看就是危险的；确认时要人亲手打出指定文字，光点「确定」不算数。

给人用的备份只在数据管理。记忆页不放第二套备份 / 恢复。

**让人在一堆东西里找某一个的列表，按名字排好。** 设置里的内置技能、我的技能，都按名字拼音排（中文在前、英文在后，数字按大小），具体写在输入框的设计里（技能列表按拼音排）。排的是眼前看到的名字：内置技能界面是英文就按英文名排。例外：技能市场保持市场自己的顺序，那顺序本身在说推荐程度；有先后含义的（开着的、加载过的）保持先后。

### 明确不做的事

- **不为了统一而牺牲页面本来就对的交互。** 一个整块可点击的控件，不能因为「要跟普通设置行长得一样」就退化成一行摆设。视觉一致服从于交互正确。
- **不动设置项本身的功能与含义。** 这轮只解决「长什么样、怎么摆」，不改任何设置的行为，也不删改设置项。
- **不为个别主题打专用补丁。** 一个视觉问题如果只在某套主题下修好，那它在其余主题下多半还坏着——历史上就是这么埋下十套主题卡片凹陷的。要么在所有主题下都成立，要么不算修好。
- **不写用户没法据此行动的提示。** 一条提示要么说出一个具体后果、让人知道该做什么或不该做什么，要么就不写。「请确保设备安全」这类话既没指出真正的风险，也不给人任何可做的事，只是占着一块显眼位置装作在负责。带颜色的告警条尤其要省着用——用多了它就不再意味着「这里要当心」。

## 行为契约

- 面板内容不随窗口宽度无限拉伸。项目名与它对应的控件，始终保持在一眼能关联起来的距离内。
- 卡片在任何一套主题配色下都必须与页面底色分得开。不允许出现「看不见卡片」或「卡片陷进去」。
- 描述性文字在任何主题下都要能正常阅读，不能暗到需要凑近看。
- 开关、分段选择等控件可以用键盘操作，并且有看得见的焦点提示。
- 分组标题在视觉上必须明显退后于设置项名称，让用户一眼能分出「这是一组」和「这是一项」。
- 页名、分组标题、设置项名三级在字号与轻重上依次递减，任意一页扫下来都能看出这个层级。
- 页头里的页名与侧栏当前选中项一致，不出现两个说法。
- 相关的设置项归入同一组，不一项一张卡。一项独占一张卡时，两条设置之间的空白会比设置本身还宽，看不出它们是相关的一组。
- 同一组互斥档位等宽，不因各档字数不同而参差。宁可让字少的档位留白，也不要一排宽窄不一的按钮。
- 选中即放弃一道保护的档位（如让 AI 不再逐条征求确认），要用警示色标出，让代价一眼可见，而不是与普通档位同色。
- 只读的现状信息只在真有情况时出现，一切正常时不占位置说「一切正常」。用户读到「没事」既不会因此做什么，还会稀释真出事那次的对比度；何况出事时本就有更靠前的渠道（如启动时的弹窗）会主动找他。
- 按钮全面板用同一套，页面不自制。此前有页面自己写了一套仅供本页使用的按钮，尺寸与悬停表现都和别处不一样。
- 选项不超过三四个且文字短的，摊成一排档位让人一眼看全；更多或更长的才收进下拉。同一种取舍在所有页面保持一致，不由页面各自决定。
- 输入框、下拉、滑块也各只有一套外观。滑块必须常驻显示当前读数，否则拖动时只能靠猜。
- 一页里的设置项超过十条时，必须按用途分组，不能平铺成一列。十几行长得一样、又没有中途歇脚处的列表，用户找不到想改的那一条。
- 页面的说明文字挂在它解释的那一项上，不堆成一整段放在分组开头。一段话里同时解释两个按钮，读的人得先把话拆开再对号入座。
- 页头下方的第一段说明与紧接着的第一个分组标题，不允许是同一句话的两种说法。页名已经在头上了，分组标题若只是把页名换个词再说一遍，那一层就该去掉。
- 几乎每次打开都要看、都要用的内容在上面；改完就很少再碰的设置在下面，不占第一屏。
- 有未保存改动的页面，用户从任何出口离开都会先被问一次，包括点侧栏切到别的页。
