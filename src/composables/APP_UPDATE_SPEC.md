# 应用内更新提醒

## 设计目标

- **更新是后台的事，不打断人。** 自动检查、自动下载的整个过程里，界面不弹窗、不弹进度卡，失败也不弹警告。
- **只在两种时刻主动找用户**：新版本已经下好、可以安装了；这台机器没法自动下（macOS，或用户关了自动下载），需要用户决定要不要去下。
- **谁在等，就当面说给谁。** 用户亲手点的检查和下载，进度与失败都留在他点的那个地方：在「设置 → 关于」里点的，就在那一页；在右下角提醒卡上点「下载更新」的，就在那张卡上。后台自己做的事，进度和失败都不出声，下次检查再试。
- **关掉「可以安装了」的提醒，不等于放弃这个版本。**
  - 开着「退出时安装」：关掉 = 这次先不重启，退出应用时再装。
  - 没开：关掉 = 这次先不装，下次启动后再提醒。
  - 想马上装，随时可以在「设置 → 关于」或帮助菜单里装。
  - 按钮上写的话要和实际行为一致：写「稍后提醒」就必须真的再提醒，不能变成永远不提醒。

## 行为契约

- 开着自动下载时：发现新版本，悄悄下载，下完弹一张「可以安装了」的提醒卡。下载期间只有帮助菜单里一行灰色的「正在下载」和「设置 → 关于」里的进度可看。
- 提醒卡的三个出口：安装并重启；退出时安装（或「稍后提醒」，取决于上面的开关）；关闭（和第二项等效，并用一句提示告诉用户接下来会怎样）。
- 关了自动下载、或在 macOS 上：发现新版本时弹提醒卡，由用户决定去下载。
- 用户在提醒卡上点了「下载更新」：这一次的下载进度留在卡上。关掉卡片下载继续，下完仍会提醒安装。首选更新源失败自动换源重试期间，卡上的进度继续走，不冻住、不消失。
- 用户转去「设置 → 关于」里点了下载：还开着的「发现新版本」卡自动收起，进度只在那一页，不留一个能重复点的下载按钮。
- 一个版本在这次启动里已经下好并提醒过，之后再检查到它，不回头弹「发现新版本」。
- 后台检查或下载失败：不弹任何提示。用户之后打开「设置 → 关于」，能看到最近一次的结果，并可自己重试。

## 暂不做

- 自动下载失败时自动换另一个更新源（用户手动点下载时才会换）。2026-10-23 讨论后决定这一轮不改。
