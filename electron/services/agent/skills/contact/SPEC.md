# 本地联系人（contact）

> 落盘：2026-10-13

## 设计目标

秘书要能**稳定地认人**：听到一个名字或简称，找得出这是谁、在哪个单位、什么角色、邮箱和即时通讯怎么找到他。旧做法是一份让模型自由增改的 Markdown 笔记，用久了会出现同一个人两条、同类信息写法各异、邮箱埋在句子里，模型还会整篇重写。这和当初待办从笔记改成结构化记录是同一个原因。

- **只做「认人」这一层**：每人一条，记姓名、别名/简称、是人还是机构、单位、角色、邮箱 / 电话 / 即时通讯，外加一段自由备注。关系和近况写在备注里，用人话，不拆成字段。
- **同一个人不记成两条**：新增时按姓名和别名比对，完全对上的不新建，把补充的信息并进原来那条。只是名字里有同一个字不算对上。
- **写入只走工具**：秘书不能直接改联系人文件；旧笔记也不再在免确认名单里。
- **用到才查**：联系人不进心跳，不在每次对话里整本带上。它和待办不同，没有截止、没有状态，不需要定时提醒。
- **不做**：往来记录、组织架构、桌面联系人面板、待办那种状态与排序。
- **以后的方向**：即时通讯里「各渠道最近联系的人」、邮件里的地址，日后挂到同一条联系人上，不另存一份。本次不做。

## 旧笔记怎么过来

- 升级时先把旧笔记备份一份，原文件不动。
- 程序不猜 Markdown 格式。由联络问一次要不要整理，用户同意后秘书读原文，逐个记进来；原文里没有的邮箱、电话不补。用户说以后再说，下次启动再问；说不用了，就不再问。
- 待办的迁移还在等用户回话时，联系人这次先不问，免得两件事同时打扰。
- 只有秘书明确记下「迁完了」之后，旧笔记才收进备份。征询期间秘书顺手记了几个新认识的人，不算迁完。
- 迁完之前，查不到的人会提示旧笔记里可能有，秘书可以去翻那份。
