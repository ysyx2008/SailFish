# 后台远程通道

## 设计目标

让软件能在用户已存的 SSH 主机上**后台跑一条命令、拿回结果**，不开终端窗、不占窗格。它是通用的底层：不认得谁在用、不认得在干什么活；谁能用、能跑哪些命令，由上层的授权决定，不在这里。

成功标准：同时对几十台主机各跑一条命令，不会把对方的登录服务、跳板机或本机拖垮，也不会因为一台主机出问题连累其它主机。

关键取舍：

- **不开终端**：命令在没有交互界面的通道里跑，输出整段收回。需要手工输入的登录方式（只给交互提示的跳板机、要二次验证的主机）这里不支持，直接说清楚「连不上、为什么」，不假装能行。
- **和终端用同一份主机设置**：地址、账号、密钥、密码、跳板机（包括分组继承的跳板机）与终端窗口一致，用户不用再配一遍。
- **尊重对方的承受力**：
  - 同一时刻向外握手的连接数有上限；
  - 一台跳板机同一时刻转发的连接数有上限，多出来的主机排队，不一拥而上；
  - 同一台主机的连接用完先留一会儿给后面的命令复用，闲置久了再关；
  - 密码或密钥被拒绝不重试，同一份登录信息连着被几台主机拒绝就先停手，免得把账号锁了；
  - 跳板机明确禁止转发的，只说一次，之后经它的主机不再去试。
- **失败要说清楚**：每台主机各自返回结果——成功、退出码、超时、被中止、连不上（并说明是认证失败、连不通、跳板机禁转发还是别的），不抛一个笼统的错误吓住整批。
- **能停**：命令超时或被中止后，远程那条命令必须真的结束，不留残余进程占着对方的机器；等不到结束时强制放弃这条连接，不让调用方一直等。
- **输出有上限**：单条命令的输出超过上限就截断并标明，不把内存吃光。
- **不关心主机身份校验**：与终端窗口一致，不校验主机指纹；这一点是已知的取舍，不在这里单独改。

明确不做：

- 不做交互式会话、不分配终端给命令（除非后面实测发现某些远端不这样就杀不掉命令）。
- 不做命令是否安全的判断：那是授权层的事。
- 不保存、不记录命令的输出：交给调用方处置。

## 行为契约

- 一次调用对应一台主机一条命令，返回该主机的结果；不同主机之间互不影响。
- 调用方中止时，排队的不再去连，已经在跑的结束掉。
- 整个通道可以一次性关掉：所有连接关闭，所有在跑的命令按「被中止」返回。
- 用本机真实的 SSH 服务验证过：超时和中止之后，单个进程、带子进程的命令、管道里的进程、后台进程都会消失。很旧的远端 SSH 服务不支持「发信号结束」时是否仍会留下进程，没有验证过。
