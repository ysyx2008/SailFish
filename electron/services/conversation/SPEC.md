# Conversation 模块 SPEC

> Last verified: 2026-08-27

## 职责

会话领域模型：`Conversation` 聚合根、策略表、`Companion` 关系线、transcript 切分。

## 设计目标

### 对话怎么动只有一种做法，界面只是界面（2026-10-10）

- **问题**：桌面上发出一句话之后，「这是新开一场、往正在跑的那场里补一句、还是接着做停了的那场」有一半在聊天窗口里判断；联络替用户管理任务时又另写了一份。两份各自演化：联络管的任务和用户自己操作的效果对不上，以后改了一处，另一处不会跟着变。
- **成功标准**：新开一场、往一场里说一句（在跑就当场补进去，停了就接着做，不在眼前就从历史接回原来那场）、批准或拒绝、停止——每件事只有一种做法。桌面图形界面、命令行、IM、网页、联络替用户操作，走的都是这一种；不管谁做的，打开着的界面都立刻看得到。
- **关键取舍**：
  - 界面只负责收输入和显示：打字、附件、图片、排队、先把话显示出来。做事和判断都不在界面里。
  - 别处（联络、IM、另一个界面）动了某场对话，桌面上那场立刻出现在侧栏，话和过程照常显示；「正在跑」以实际执行为准，不以界面自己的记号为准。
  - 只有窗口才知道的东西（终端屏幕上的内容、工作台给的提示）由界面在说话时一并带上；没有窗口的场合就不带，照样能做。
  - 不是从窗口里说的一句，接着用这场上一轮的终端窗口；那扇窗已经关了就不用。
  - 本机终端那场在界面上接不回来（终端开不出来）时，这一轮停掉，不对着没有窗的终端瞎跑；助手那场没有窗也能做完，结果照样进历史。
- **明确不做**：不靠模拟点击去操作界面。

### 审批方式是每场对话自己的（2026-10-10）

- **问题**：审批方式（严格 / 宽松 / 替我审批 / 全自动）原来只有一个全局设定，在任何一场里改，所有对话一起变。联络想给交办的某场任务定「全自动」或「替我审批」，只能在后台另开特例，界面上看不到，那场重启后也就不记得了。
- **成功标准**：每场对话有自己的审批方式，输入框下拉框显示和修改的就是眼前这场的；在这场里改，别的对话不受影响。审批方式记在对话里，重启、接回、换个界面继续，都还是那一种。
- **关键取舍**：
  - 在「新对话」起始界面上选的，是之后新开对话的起步值；进了某场以后再改，只改这一场。
  - 联络建任务时给那场选审批方式，等于用户在那场里选：没说全自动就是替我审批。它只管那一场，不改用户的起步值。
  - 以前的对话没有记下审批方式，打开时按当时的起步值算。
  - 正在跑的时候改，这一轮接下来就按新的方式问。
  - IM、网页、关切、命令行这些渠道自己定了某一轮怎么问的，那一轮按渠道的来，不改这场记下的方式。
- **明确不做**：IM 渠道自己的审批设定这次不动；网页 / IM 接进来的远程会话，以及联络（多个渠道汇成的一条线，桌面和 IM 本来就同一档），下拉框仍改的是渠道自己的设定。

### 删对话时，对应的回忆一起走（2026-08-27）

- **问题**：侧栏删掉一条对话后，秘书仍可能在回忆里翻到它。
- **成功标准**：用户删一条对话，这条对话对应的知识库检索条目一起去掉。
- **关键取舍**：对得上号的才删；对不上的旧条目先留着。
- **明确不做**：不扫整库清旧账；不删对话里记下的长期事实。

### 新对话何时进历史

- **问题**：以前新对话要等第一次任务跑完才写入历史。进行中崩溃、切走再回来，这条对话会丢或从侧栏消失。
- **成功标准**：用户发出第一条消息后，这条对话就进历史；之后任务进行中持续记下进度，中途崩溃最多丢掉没写完的那一轮，整段对话还在。
- **关键取舍**：认「已经开了头的会话」，不认「已经跑完的历史」。
- **明确不做**：只点了新对话、还没说话，不进历史（避免一堆空白条目）。联络 / 关切 / 唤醒各自原来的进出规则不变。

### 侧栏标题跟着聊，但手改过的不碰（2026-08-17）

- **问题**：标题只根据用户第一句话生成。聊着聊着事情变了，侧栏还停在开头那句，不好认。
- **成功标准**：新对话先用第一句话出个标题，方便马上出现在侧栏。之后每完整说完三轮（一轮 = 用户发一条并跑完，中途追加不算），趁着刚聊完再根据整段对话重写一次。人手改过的名字，之后不再自动改。新标题和旧的几乎一样时，侧栏不动。
- **关键取舍**：按固定轮次刷新，不猜「话题换没换」。标题是路标，不是实时摘要。
- **明确不做**：联络、关切、唤醒不跟这套。不把「请起个标题」写进用户看得见的对话。说不清是不是手改的旧记录，按可以自动更新处理。

### 联络时间线不被主动提醒挤掉（2026-08-19）

- **问题**：心跳、关切每次主动找人都会单独记一条。联络页按「最近几条记录」拼时间线时，这些提醒把真对话挤出去，打开只剩几条催办，昨天聊过的话看不见。启动时如果提醒已经先到了，整段历史还会干脆不恢复。
- **成功标准**：打开联络能看到最近大约十段真对话，夹在中间的主动提醒还在。提醒再多也不占真对话的名额。启动时已经弹出的提醒不会挡住历史；接上之后提醒还在、不重复。
- **关键取舍**：名额按「真的聊过」算，不按「落盘了几条」算。
- **明确不做**：不把全部联络历史一次铺开。不改任务侧栏。不删已经记下的提醒。

## 从这里创建任务（companion → task）

用户在联络里点某条消息「从这里创建任务」时，设计意图是：

**以当前这条为终点；不要带上这条之后的消息；终点之前，由 AI 挑出和这件事相关的几段带上，而不是机械地按时间硬截一段。**

### 由 AI 挑相关的对话（2026-10-11）

- **问题**：按时间连着往前截，会把这几小时里无关的话整段带进来，又可能把更早、但其实是这件事开头的高相关对话截掉。
- **成功标准**：新任务里带的是和这件事相关的几段对话，一整段（用户说的、秘书回的、做过的过程）要么整段带、要么整段不带；你点的那一段一定带上，它之后的不带。
- **挑选方式**：候选是联络当前屏幕上、你点的那一段之前的所有用户对话。挑选在联络眼前这场对话之后补一句说明，让同一个模型从编好号的各段简述里选；这样能接着联络刚聊过的缓存，不必把历史重新读一遍。回复先给要带上的段号，下一行是这场新任务的侧栏短标题。简述每段只有用户说了什么、最后落到哪。候选段数设一个上限，避免简述本身过长。
- **点在主动提醒上**：只带这一条，不往前挑，也不发这次挑选。
- **紧挨在选中段前面的主动提醒**一并带上（常见「通知 → 用户接着回」）。
- **等待**：挑准比快重要，不为赶时间提前放弃。点下去后界面有进度提示：一条一直在走的进度，并显示已经等了多久；模型若交出思考过程，提示底下跟着它正在想的最新几句（只在等待时看，不写进新任务）。模型不交出思考过程时，仍只显示进度和已经等了多久。结束就收起。总时长说不准，不用走到百分之百的进度。
- **兜底**：挑选请求失败、回的内容对不上序号时，按下面「时间窗口」的老办法开出任务，按钮不会一直转。联络眼前没有可接的上下文时，仍发一次挑选，只是带的是简述、接不上缓存。
- **明确不做**：不为了赶时间限定几秒；不让 AI 复述原文（回序号比复述快得多）；不带终点之后的话；不把半段过程带进来。

### 挑选时一并起标题（2026-10-16）

- **问题**：开出来的新任务，侧栏上写的是你点的那一句，几段拼在一起时往往对不上这场在做什么。再单独问一次模型起标题，等于把刚看过的内容又读一遍。
- **成功标准**：同一次挑选里，给出要带上的段号之后，再给一个侧栏短标题。新任务一出现就用它。标题只根据将被带进去的那些段来起。
- **没有标题时**：段号对得上但没给出可用标题，或这次没有挑选（点在主动提醒上、只有你点的那一段、挑选失败改走时间窗口），侧栏仍用你点的那句话。段号之外只多出标题那一行；再多出别的话，仍算对不上，走时间窗口。
- **之后**：跟别的自动标题一样，你亲手改过就不再自动改；之后每完整说完三轮，仍可以按整段对话重写。
- **明确不做**：不为起标题再单独请求一次；不把起标题写进你看得见的对话里。

### 带过去的是历史，接着说时先冷启动一次（2026-10-16）

- **问题**：从联络创建任务后再接着说，发出去的请求里没有系统提示。身份、规则、技能说明、知识和环境都没带上。
- **成功标准**：带过去的是这段对话的历史。你接着说的第一轮按一场新任务冷启动：重新组系统提示，再把这段历史装进去。这一轮之后就跟普通任务一样接着聊。
- **关键取舍**：不把联络当时发出去的那一份原样接上。那一份里没有这场任务该有的系统提示，接上之后就补不回来。
- **明确不做**：不在创建的当下就发一轮请求。不把联络做过的交接检查点原样接着用。

### 时间窗口（挑选失败时的老办法）

以当前这条为终点，倒序往前取一段上下文：
- 按用户对话扩窗（间隔约 6 小时内、最多约 10 段）；主动通知不当切断点。
- 窗口内的主动通知要带上；紧挨窗口第一条用户话之前的那条通知也要带上（常见「通知 → 用户接着回」）。
- 若点的就是主动通知本身，只带这一条。

实现入口：`Companion.extractTaskWithLiveOverlay` → `Conversation.extractTaskFromRecords`。
与 task 的「另开一聊」（从头截到第 N 个）不是同一套语义。
