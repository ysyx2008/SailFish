# CLI（无头模式）

> Last verified: 2026-10-20

## 职责

提供无头 Agent / 运维命令入口。开发态与打包态共用命令面（`runCli`）。

## 设计目标

### 在终端里能读完、能接着说（2026-10-20）

- **问题**：跑一轮时，思考用的网页标记、工具参数、内部日志和「没有窗口」的报错混在同一屏，人没法读；提问和确认也埋在里面。另外秘书不站在你敲命令的那个目录，而是回到用户主目录去找「这个项目」。
- **成功标准**：秘书说的话按原文往下长；它做了什么是一行行的过程；思考过程不倒出来。需要你点头或回答时，单独问清楚，你打一行就能继续。在终端里说完可以接着说。你在哪个目录里敲的命令，它就在哪个目录里干活。
- **关键取舍**：过程从简，正文从详。内部日志留在日志文件里。没有图形窗口是命令行的常态，不当成故障刷屏。
- **明确不做**：不在命令行里复刻桌面的卡片、折叠思考和会话历史面板。

### 同一屏里接着干活（2026-10-20）

- **问题**：什么都不带、只敲开命令时，要有一块能待着的地方：输入在底下，上面是这场对话。文件拖进终端、技能的查看和加上，都在这块地方完成。带上一句话时不是进这块地方，而是直接开工。
- **成功标准**：自己开着终端、什么都不带，就进入这一屏。拖进来或粘贴的、确实存在的文件路径，按桌面贴文件的同一条路附上。这一屏里能看到技能、加上、拿掉。带上一句话则直接让秘书做，字在原来的终端里往下走。从别的程序接进来，或明确说了说完就走，答完即离开，不进这一屏。
- **关键取舍**：两扇门分开。带任务不进这一屏。管道和说完就走仍是纯文本。
- **明确不做**：不在这一屏里复刻桌面的卡片、折叠思考和会话历史面板。不另造一套附件或技能的记法。

### 命令行里也能挂目标（2026-10-20）

- **问题**：想交代一件要做完的事、让秘书自己推到底，不该只有桌面能做。命令行最适合无人值守地丢一个目标出去，回来看结果。
- **成功标准**：
  1. 和桌面同一种写法：`/goal 目标` 挂上并开跑，`/goal` 看状态，`/goal pause`、`resume`、`clear`、`edit 新正文` 管理；以 `clear`、`pause` 开头的一整句话仍然是目标正文，不是命令。带一句话开命令（`sailfish "/goal 把测试跑绿"`）、在终端里接着说、同一屏里输入，都认。
  2. 挂上之后，这一轮收工时目标还在推进，就自己接着推，直到达成、停滞、额度不够、预算用尽，或你按 Ctrl+C。续跑的每一轮在过程里留一行，看得出是在接着推，不冒充你又说了一句。
  3. 跑完说一句结果：目标现在是什么状态、花了多久、花了多少 token；没做完的说清下一步（继续用 `/goal resume`）。目标没变化、没花新用量的轮次不重复说。
  4. Ctrl+C 是暂停，不是清除，之后能用 `/goal resume` 接着推。
  5. 清掉没做完的目标、用新目标换掉没做完的目标，会问一句；已达成的直接收起。没有交互终端时不替人答应，这两件事不做。同一屏里这一轮还在跑时，换或清没做完的目标不弹确认，请先 Ctrl+C 停下再来，目标原样不动。
  6. 续跑不提权：该确认的还确认；没有交互终端时需要确认的那一步仍被拒绝，要自动放行请显式 `--free`，和普通任务一样。
  7. 只有任务能挂目标：`companion` 命令（联络）里不认 `/goal`。
- **关键取舍**：目标只活在这一次命令这一场对话里。命令退出，就不再推进；下一次开命令是新的一场，不接回上一次的目标（命令行本来就没有「接着上一场」）。写法、状态词、清除要不要问这些，跟桌面用同一份定义，不另起一套。
- **明确不做**：不做 `sailfish goal …` 这类独立子命令，目标只在对话里用 `/goal`；不在命令行里设 token 预算（沿用不设上限）；不做跨次续跑。

### 开发态不碰真实数据（2026-08-21）

- **问题**：从仓库跑命令行做验证时，任务会写进桌面真实历史，侧栏出现一堆测试对话。
- **成功标准**：从仓库跑的命令行默认写到独立虚拟目录，桌面侧栏看不到这些记录。装好的正式命令仍然跟桌面共用真实数据。
- **关键取舍**：开发默认隔离，只借用模型配置和密钥，不借用历史。要碰真实数据必须显式说。
- **明确不做**：不改桌面 App 自己的数据目录；不把装机后的正式命令改成默认沙箱。

## 入口

| 入口 | 场景 |
|------|------|
| `electron/cli/main.js` | 开发：`npm run sailfish`（`sft`/`cli` 为别名；tsx + electron-shim） |
| `electron/cli/cli.ts` → `dist-electron/cli.js` | 打包：`ELECTRON_RUN_AS_NODE=1 SailFish.app/.../SailFish cli.js` |
| `~/.local/bin/sailfish` | 薄壳（设置页安装或 `npm run install:cli`） |

## 数据

- **从仓库跑**（开发入口 / 开发态薄壳）：默认进虚拟目录，借用桌面的模型配置和密钥
- **装机后的正式命令**：默认与桌面共用真实数据
- **`--sandbox`**：显式进虚拟目录（装机命令要隔离时用）
- **`--share-desktop`**：开发态显式改用桌面真实数据
- 回归测试用一次性临时目录
- Agent 默认 **`--mode relaxed`**；`--free` 跳过确认
- 命令结束后 **`process.exit(0)`**（`main.js` / `cli.ts`）；`agent:run` 另调 `AiService.dispose()` 关掉 keep-alive，避免空转十几秒才退出

## 命令面（摘要）

- `sailfish "任务"` / `--task` / `agent:run` → Agent
- `sailfish companion <消息>` → 以联络身份对话（见下节）
- `models` / `history list` / `watch list` / …
- 冒号内部命令仍可用
- 对外命令名：`SFT_CLI_NAME`（默认 / 薄壳均为 `sailfish`）

## companion 命令（联络）

无头回归联络专属能力（任务管理工具仅对联络注册，普通任务入口测不到）。

- **同一条联络线**：与桌面/IM 共用同一个联络身份与历史，CLI 里说的话桌面联络侧可见、可续。
- **联络等着任务回来**（2026-10-18，原「任务值班」）：联络派出后台任务后（CLI 无窗口，任务由后端直驱执行），联络这一轮不收工，等任务的回执在同一轮里送到，由联络回复，回复打印出来——和桌面一样，不再由 CLI 另外轮询（见 `agent/SPEC.md` 联络任务管理）。等的时候在终端敲的每一行都是对联络说的话，包括联络转述任务的确认或提问之后用户的回答（走的是和微信上一样的秘书转述）；联络自己的操作要用户确认时，那一句 y/N 不会被当成对联络说的话。没有终端（脚本、管道）就不读输入。`--mode free` 下任务本就不问。`--task-wait <秒>` 是联络为任务等的上限（默认 600；`0` = 派完就收工，回复后即退出），到点不再等，打印没做完的任务后退出。
- **退出前必须冲刷回执**：任务结束的回执有防抖窗口，进程退出前立即冲刷，联络没来得及处理的回执也要留在联络的记录里。

装机薄壳见 `electron/services/SHELL_CLI_SPEC.md`。
