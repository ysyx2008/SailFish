# Claude CLI Code Review

当完成新功能开发或较大规模的代码修改后，使用本机已安装的 `claude` CLI 对改动进行一次代码审查。

## 流程

1. 通过 `git diff` 获取本次改动内容
2. 调用 `claude -p` 将以下信息传入，请求其进行 code review。不要加 `--tools ""`，也不要禁止它打开文件。
   - **修改目标**：本次改动要解决什么问题、实现什么功能（一两句话即可）
   - **diff 内容**：`git diff` 的输出
   - **相关文件上下文**：这次问题明显依赖、但 diff 里没有的代码，一并附上
   - **速度**：把下面这段原样放进提示词

```
材料是这次改动的目标、diff，以及我认为相关的几处代码，不一定齐全。仓库就在当前目录，可以打开其他文件、跑命令；写进去的文件会留在我正在改的工作区里。我在等这次审查的结果，多读一个文件、多跑一条命令，等待就长一点。
```

3. 审查关注点：
   - 实现是否正确达成了修改目标
   - 代码健壮性、安全性、性能、可读性与可维护性
   - 是否有遗漏的边界情况或副作用
4. 根据审查结果自行判断是否需要采纳和修复，无需用户确认，修复后简要告知用户改了什么及原因
