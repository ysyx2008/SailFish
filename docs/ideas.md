# 旗鱼想法本

点子先记在这里。想法会很多，一律记下，不筛。这不是待办清单：想法是还没验证的东西，没有「必须做完」的意思。讨论之后可能觉得不要做，也可能真的就做了；做了也可能不太满意，先搁在分支里，暂时不上线。想法要花时间才变成方案，方案要花时间才变成功能。这个本子就是那段时间差的收容所。

翻的时候看四堆：**未完成**、**已完成**、**做成了但不上线**、**不做了**。一条后来怎样了，对照提交和还没合进来的分支就能看出来——上线了就挪到已完成并挂提交；做了但不满意、还在分支里，挪到「做成了但不上线」并挂分支名；讨论后决定不做，挪到不做了，留一句为什么。**做完了就改本子**，不等下次才补。

已经写成独立方案、还没勾完的，仍在 `docs/plans/`（文件名没有 `done-` 前缀的就是）。那些不必再抄一遍到这里。

- **记下**：2026-09-26
- **想法**：是不是可以专门实现一个「编程」工作台，独立于现有的助手、终端之外。主要是给 agent 在编程场景下用的工具。同日对齐：定位是「秘书能更好地接手编程活」，不是做 IDE。现在也能做，但做得不够好，主要是缺好用的工具。Cursor 和 Claude Code 也在淡化 IDE，算殊途同归。目标是能替代它们完成一些不太复杂的编程任务，不是去指挥它们。编程专用的新工具只在编程台里出现，像人要编程就开 IDE，不再用记事本。
- **方案**：讨论稿见 [docs/plans/2026-09-26-coding-workbench-design.md](plans/2026-09-26-coding-workbench-design.md)。同日再定：一个编程台绑一个项目；第一版只做本机；六类能力（看得懂、改得准、能自证、git、给人审、懂项目规矩）一次做全。同日：担心软件做太重，定下重东西按需下载、只在编程台开着时运行；大项目只靠搜索不够，要有 Visual Studio 类浏览器那样的结构理解（含查函数引用）。CodeGraph 太大不内置，改为自建轻量引擎，CodeGraph 只当验收对照。随后暂缓：先不考虑编程，在想编程是不是另外发布一个软件、而不是集成进旗鱼，未定。同日补充：已有用户在用旗鱼现有功能写简单的软件，也能做。同日又想：编码作为高级能力，做成默认不打开、类似内置技能的功能——一般用户用不上，高级用户自己打开。研究结论：现有技能系统够用，要补默认关、项目目录、子 agent 继承三处；打开时才下载，安装包几乎不变。随后定：初版不做类浏览器 / 结构索引，像 Claude Code 那样靠搜索、读、改、跑命令。摸底发现：现在工具只按本机、远程、助手三种形态开关，后端不知道自己在哪个工作台里；工作台声明的技能也只登记、没接通。所以「只在编程台出现」需要让工具多一道按工作台开关的门，得沿用现有的工作台分类，不另起一套。还有几件事待定（见方案 §7），未开工。
