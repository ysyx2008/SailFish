### 想法 · 接入火山方舟的「决策评估」（只判断、不写字的快模型）

- **记下**：2026-10-20
- **想法**：想支持火山引擎出的决策模型（方舟「决策评估」，不生成文字、只返回判断的概率，所以快）。最初是想给「替我审批」做补充；设置里要能单独添加这一种模型，不能混进聊天模型里。用户也觉得这类「系统 1」模型有意思，只是在替我审批里用武之地不算大，让一并看看别处能不能用。
- **方案**：还没有。讨论到的方向：
  - 替我审批：它没法替代现在的评审员（不能先只读查一眼、给不出理由，只有一个模型、还在测试期）。用法有三种——和评审员并行只管否决、先筛一道明显不对的直接问你、明显没问题的直接放行；第三种和替我审批现有的两条「明确不做」冲突，要先改设计。用户倾向第三种、放行门槛和评审员同一张表；但这件事次数少、错放代价大，恰好是它最不擅长的一类。
  - 更对口的地方（只看了代码，没测过快多少）：①知识库检索重排——现在默认开着，每次候选多于要返回的就多一次完整的主模型调用，再用正则从回答里抠序号；它本质是打相关度分，最对口。②邮件来信筛选——现在只按发件人 / 主题子串匹配，意图说不清的来信也会叫醒完整 Agent。③命令风险分级给「只升不降」的补充。关切 / 唤醒前的预检早已被程序分流（攒批、静默时段）替掉，且唤醒是秘书自己的节律，不适合再加一道闸。

### 想法 · 读文件工具报的总行数比实际多 1

- **记下**：2026-10-21

- **已落实**：读文件报的总行数与 `wc -l` 一致；读最后几行拿到真正的最后几行，不再是一行空白；前 N 行正好读完整份时不再说只读了一部分；整份读不再多编一个空行号；空文件报 0 行并明说是空的。末尾没换行的文件结果不变；写文件的按行插入 / 替换没动。仓库 400 个真实源码文件对过 `wc -l`，全部一致。`f7305706`
