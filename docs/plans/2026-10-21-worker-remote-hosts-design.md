# 伙计在已存主机上后台干活 · 方案

状态：**未完成**（2026-10-21 落盘，等用户审方案，尤其是文末的提示词草稿）

分支：`feat/worker-remote-hosts`

设计目标已写进：
- `electron/services/agent/SPEC.md`「伙计可以在派给它的已存主机上后台干活」；「伙计不碰终端窗」第 2 条补了一句；「伙计能看见什么工具」补了一句
- `electron/services/agent/command-audit/SPEC.md` 设计目标「查看用的子命令按安全算」「只读判定比『安全』更严」

## 要解决的事

伙计不碰终端窗，只能在本机跑命令，大批量伙计用不到几十台服务器上。用户已存的主机清单里有登录信息和跳板设置，想让伙计用它们在后台干活。第一个场景是批量巡检，但不能只为巡检做。

## 已定的取舍（讨论结论）

- **只做两层**：
  - **后台远程通道**是通用的底层，不认得谁在用；
  - **授权**（范围 + 派出前一次批准）接在现有审批门上，不另立一道。
  - 巡检、拉日志这些具体做法不另做东西：由秘书按活组织，想固定成一套清单就用现有技能写。代码、工具名、文案里都不出现「巡检」。
- 安全边界由代码保证，不靠技能。
- 这一期只给伙计用；秘书自己看远程仍开窗。
- 远程只读：单上的命令先过远程只读判定，再交用户批。
- 照单执行，一字不差；单外的不跑，写进结果；补单交给原来的伙计，同样要用户批。
- 批准跟这场对话的审批方式走（2026-10-21 改，原先「只能由人批」太严）：
  - 严格、宽松弹卡；替我审批先过评审员；自由模式不弹，单子照样生效；
  - 按中等风险定档，宽松档也问；
  - 「本次允许」不特殊处理：派伙计的允许键是整份参数，只有一模一样的一批才会命中；
  - 关切、唤醒一律退回（它们的自由模式是系统定的，不是用户选的）；命令行没人值守时，显式自由模式可派，否则退回。
- 卡上只能整单批准或拒绝；拒绝可附一句原因。
- 伙计手里的远程命令工具按处境出现：派出时范围里有主机就有，没有就没有。秘书不必先装技能。
- 一个伙计管几台由秘书定；照样受「没做完的不超过 200 个」那条限制。
- 读出的敏感内容这一期不过滤，卡上写明「输出会交给模型」。
- 不经模型的批量分发、通道给评审员/关切/秘书用、本机批量活的派出前批准：都记进想法本，不在这一期。

## 数据与边界

### 派出参数（`dispatch_agents`）

- `tasks[i].hosts` / `batch.items[i].hosts`：`string[]`，已存会话的 `sessionId`（`list_ssh_sessions` 返回的那个）。
- 顶层 `remote_commands`：`string[]`。这一批共用一张单；任一伙计带了 `hosts` 就必填。
- 派出流程（都在真正 `roster.spawn` 之前）：
  1. 解析任务。所有 `hosts` 必须是存在的已存会话，否则整批退回。
  2. 逐条跑远程只读判定。有一条不过就整批退回，回执写明第几条、为什么。
  3. 关切 / 唤醒（`unattended` 的后台执行）整批退回。
  4. 执行档是 free 就跳过确认；否则 `waitForConfirmation(..., riskLevel: 'moderate')`（宽松档也调用，不走 `commandNeedsConfirm`），带上卡片要用的结构化内容：主机按分组归好、命令清单。替我审批照常接在里面；没有确认渠道时它本来就按未批准返回。
  5. 拒绝就整批退回，带上用户写的原因（评审员没放、交给用户后用户拒绝，同此）。
  6. 批准就 spawn。每个伙计的 `RemoteGrant { hosts, commands }` 跟着他走，不可由他自己改。

### 补单（`followup_agent`）

- 新增可选 `remote_commands: string[]`。
- 同样过只读判定，再按同一套审批方式确认（卡上写明补给谁、他的主机）。批准后追加进这个伙计的 `RemoteGrant.commands`，再把消息交给他。
- 没有主机范围的伙计不能补远程命令（他本来就没有远程工具，不在中途给）。

### 伙计侧工具：`remote_exec`

- 只在 `RemoteGrant.hosts` 非空的伙计工具清单里出现。
  - 清单里按处境加入，运行时再校验一遍；没有授权的调用直接拒。
  - 不进秘书、不进普通伙计；`ToolMeta` 上新增一种「只给有远程范围的伙计」的标记，不靠名字判断。
- 参数：`host`（sessionId）、`command`、`timeout_seconds`（默认 60，最大 600）。
- 校验：
  - `host` 在范围里；
  - `command` 原文去掉首尾空白后与单上某条完全相同。
  - 两条都过才执行，不再跑风险审计：单子在批准前已经判过。
- 返回：主机名、退出码（或超时 / 连不上的原因）、截短的输出。输出先按会话编码解码，超过 4000 字时留头尾。
- 完整输出写到这一轮伙计的落盘目录下 `remote/<伙计名>/<序号>.txt`。
- 留痕：在同一目录追加 `remote-ops.jsonl`，一行一条，记下时间、伙计、主机、命令、退出码、耗时、输出文件。写盘用异步追加。

### 伙计的处境说明

派出时由系统接在伙计任务后面，事实陈述，原文见文末草稿。内容是：

- 能连哪些主机：名字、user@host、分组；
- 批准过的命令清单；
- 单外的命令不能跑，可以写进结果。

### 后台远程通道（新服务，`electron/services/remote-exec/`）

- 输入「已存会话 + 分组」，自己生成登录配置。跳板规则来自共用的 `effectiveJumpHost`（见下）。
- 连接表与终端的 `SshService.instances` 完全分开，不发窗格断开事件，界面无感。
- 连接池按「谁在用」分组，这一期就是派出那位主人这一场：
  - 同主机复用一条连接，闲 60 秒自动断；
  - 同一跳板共用一条跳板连接，跳板上同时开的转发不超过 4 条；
  - 全局同时握手不超过 8 个，多的排队。
  - 这几个数是内部常量，不给人填。
- 登录失败：
  - 密码或密钥被拒不重试。
  - 同一组「用户名 + 凭据」连着被 3 台拒绝，这个池里后面的主机不再用它，直接报「已暂停用这组账号登录」。
- 跳板：
  - 拒绝端口转发、或是只能交互的 JumpServer，报清楚：沿用 `JUMP_FORWARDING_REFUSED_MESSAGE` 一类现成说明，不走 JumpServer 交互 shell。
  - 能连上但不支持直接执行命令的设备，报「这台不支持直接执行命令」。
- 执行：`client.exec(command)`，不带伪终端。
  - 超时或按停时先发信号（`channel.signal('KILL')`），再关通道。
  - 端到端验证远程进程确实没了；没了才算过。不行就改成带伪终端执行，关通道时远程会收到挂断。这一点以实测为准。
- 按停：主人这一场停下时，花名册打断所有伙计，并关掉这一池的全部连接。
- 不校验主机指纹，和终端一致；SPEC 已写明不做。

### 跳板规则挪到共用处

- `packages/shared-types/src/connection.ts` 新增 `effectiveJumpHost(session, groups)`，参数只要结构（`jumpHostOverride` / `groupId`，分组的 `id` / `name` / `jumpHost`），内部用现有的 `jumpHostFromGroup`。
- 前端 `getEffectiveJumpHost` 改成调用它，行为不变。
- 前后端各有一份 `SshSession` 定义，是已有的重复。这一期不动，记进想法本。

### 远程只读判定（`command-audit`）

- 本机评审员核查和远程共用一个判定，「处境」作为参数传入：
  - 本机：当前目录 + 本机 shell；
  - 远程：按 POSIX shell，不给自由区和工作区，`~` 不展开成本机主目录，不读用户自定义命令规则。
- 四条都要满足：
  1. 完整解析，没有不认识的命令；
  2. 整体和每个命令本身都是安全级；
  3. 没有写文件的重定向（`/dev/null` 除外）；
  4. 没有任何命令带「会写文件」（`writesTo`）或「带内联程序」（新增的规则属性 `inlineProgram`，先给 `awk`）的标记。
- 本机评审员核查也加上第 4 条，补掉 `awk` 的漏洞。
- 宽松档下 `awk` 内联程序不问就能跑，是命令审计的通用问题，不在这一期，记进想法本。

### 命令表补充

- 子命令认只读的机制：规则上加一份「这些子命令算安全」的清单。命中就按安全算，没命中照旧是规则本身的等级。
  - 这是在「只升不降」的子命令风险之外，新增的唯一一条降级路径，只看第一个非选项参数，并且仍要过选项白名单。
- 先收这些（实现时以单测表为准）：
  - `systemctl`：`status`、`is-active`、`is-enabled`、`is-failed`、`list-units`、`list-unit-files`、`show`、`cat`
  - `docker`：`ps`、`images`、`inspect`、`logs`（不带 `-f`/`--follow`）、`stats --no-stream`、`version`、`info`
  - 新收进表的命令：
    - `journalctl`：安全。`-f`/`--follow` 和 `--vacuum-*`、`--rotate`、`--flush` 不在安全选项里，按中风险算。
    - `ss`、`netstat`、`ip`：`ip` 只认 `addr`、`route`、`link`、`neigh` 后面跟 `show`/`list` 或不跟。
    - `vmstat`、`iostat`、`mpstat`、`sar`：带次数参数的才不会一直跑，按选项表控制。
    - `top -bn1`：`-b -n` 必须同时出现，否则按中风险算。
    - `dmesg`：`-c`/`-C` 不安全。
    - `free`、`df` 补常用选项：`free -g`；`df -T -i`。
- 严格档下这些查看命令不再问人，SPEC 已写明。

## 风险与对策（摘要）

| 风险 | 对策 |
|---|---|
| 一条错命令放大到几十台 | 只读 + 先判后批 + 一字不差 |
| 本机路径语义套到远程 | 远程处境：无自由区、`~` 不展开、不认本机信任规则 |
| 伙计被输出里的内容带偏去碰别的机器 | 主机范围、命令清单由代码卡死，伙计改不了 |
| 账号被锁、告警 | 不重试、同凭据连拒 3 台就停 |
| 跳板被打满 | 全局握手 8、每跳板转发 4 |
| 远程留下孤儿进程 | 先发信号再关通道，端到端实测 |
| 主进程卡顿 | 端到端量事件循环延迟，超线就挪进独立进程 |
| 敏感内容进模型 | 卡上写明；不过滤（这一期） |
| Windows 主机误判 | 这一期不支持，SPEC 写明 |

## 提示词草稿（待用户审）

以下是这次要新增或修改的、给模型看的文字。按「客观中性」原则写：只陈述处境和后果，不教做法。

### `dispatch_agents` 说明末尾追加

> 伙计也能在已存的 SSH 主机上后台跑命令：给伙计写 hosts（list_ssh_sessions 返回的 sessionId），并在 remote_commands 里列出这一批要在远程跑的命令。派出前这些主机和命令按当前执行模式走确认，批准后才开工；关切、唤醒里派不出去。伙计只能在自己的主机上原样跑单上的命令，不开终端窗。这一期只接受只读命令，有一条判定不是只读，整批不派，回执里写明是哪条、为什么。

参数：
- `hosts`：「这个伙计能连的已存主机（sessionId）。不写就碰不到远程。」
- `remote_commands`：「这一批要在远程跑的命令，每条一项。伙计只能原样跑这些。有伙计写了 hosts 就必填。」

### `followup_agent` 新参数

- `remote_commands`：「补给这个伙计的远程命令。用户批准后才交给他，他能连的主机不变。」

### `list_ssh_sessions` 说明（收敛旧的「适用场景」列表）

旧：

> 列出用户已配置好的 SSH 会话清单……
>
> 适用场景：
> - 多机巡检 / 灰度对比（dev/staging/prod 平铺为多窗格）
> - 跨主机故障排查
> - 用户说"在 xxx 服务器上看一下..."时，对照本清单找到对应 sessionId

新：

> 列出用户已配置好的 SSH 会话清单（不含密码 / 私钥等敏感字段），返回每个会话的 sessionId、name、host、port、username、group、lastUsedAt。sessionId 可以用来开窗（见下），也可以写进 dispatch_agents 的 hosts，让伙计在后台连那几台。
>
> （开窗用法那一段原样保留）

### 伙计手里的 `remote_exec`

> 在派给你的远程主机上后台跑一条命令，返回退出码和输出。不开终端，不能交互（不能输密码，不能用 vim、top 这类全屏程序）。只能跑批准过的命令，原文一字不差；别的命令、别的主机会被拒绝。超时默认 60 秒，最长 600 秒。输出超过 4000 字时只留开头和结尾，全文存成文件，路径随结果给出。

参数：
- `host`：「主机的 sessionId，见你的任务说明」
- `command`：「批准清单里的一条命令，原文」
- `timeout_seconds`：「超时秒数」

### 接在伙计任务后面的处境说明

> 你能连的远程主机：
> - web-01（sessionId: abc123，deploy@10.0.0.11，分组：生产）
> - ……
>
> 批准过、可以在这些主机上跑的命令：
> 1. `df -h`
> 2. ……
>
> 别的命令不能跑。想跑单外的命令时，在结果里写明命令和原因。

### 拒绝与退回的文字

- 单外命令：「这条命令不在批准的清单里。批准过的：……」
- 范围外主机：「主机 xxx 不在你的范围里。你能连的：……」
- 派出时不是只读：「remote_commands 第 3 条不是只读：……（判定原因）。整批没有派出。」
- 关切 / 唤醒里：「后台执行里不能派要连远程主机的伙计。整批没有派出。」
- 没有确认渠道（非自由模式、没人值守）：「这一批需要确认，这场对话里没有人能确认。整批没有派出。」
- 用户拒绝：「用户没有批准这一批。用户说：……」（没写原因就只说没有批准）
- 账号熔断：「这组账号已被 3 台主机拒绝登录，这一批后面不再用它登录。」
