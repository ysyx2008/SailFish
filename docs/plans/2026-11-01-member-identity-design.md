# 成员命名调查与已撤回的编号方案

日期：2026-11-01

状态：原结构编号及层级字段方案已撤回，相关身份文案不采用。用户确认本轮只把新成员重名后缀改成(2)、(3)，已实现待验；旧姓名、命名来源、管理关系和身份提示词不改。上一份[岗位选填文案](2026-11-01-optional-role-copy-review.md)仍单独待审核。

## 本轮实际改动与验证

- 重名成员由“目录核对-2”改为“目录核对(2)”，正常姓名不变；不加新的结构编号或层级字段，不扩展工具和保存格式。
- 138项定向单测通过，覆盖连续重名、业务编号中已有连字符、同会话休眠/跨枝占名、新旧后缀并存、旧名字原样恢复、群聊和改名回执。
- 隔离真实组织CLI验证不同组长各派一名“核对员”，实际姓名为“核对员”和“核对员(2)”，两人的真实管理归属、系统身份与落盘记录完整；组织回归106项、基础CLI104项通过（3项真实AI用例按--no-ai跳过）。后端类型、改动源码ESLint和脚本语法检查通过。自审确认仅一行生产命名规则变动，旧姓名不改，群聊、身份和落盘格式不变。

## 已核实的事实

- 成员名称目前优先取派工name，省略时从description生成；名称与存盘、点名关联，不能简单取消去重。
- 显式名称也会整理符号、截至32字符，重名加-2、-3。同一会话旧团队的人也占用姓名，避免覆盖历史记录。
- 对照本次报告中两位“派第5层组长…”／“派第6层组长…”的原始调用，上级显式填写了这样的name；description里反而写的是本人实际层级。它们不是本次从description自动生成的名字。
- 对照此前95人同一支测试记录，41位有改名记录，其中36位请求的名称经整理后已在旧团队中存在。因此不能把后缀统一归因于本轮层内同名，也不能仅凭末尾-2判定系统去重。
- 系统已经独立绑定姓名、角色、直属负责人和下派权限，父对话作为引用输入；当前缺少独立的结构编号与明确层级。不能把这些问题归结为“完全没有身份注入”。

## 原建议方案（已撤回，不作为实施依据）

1. 保留可读的显示名称与任务描述。姓名用于辨认本人负责的范围；description、prompt说明这次要做的工作。显示名不作为层位和任务业务编号的证据。
2. 由系统按真实管理关系分配结构编号，例如1、1.1、1.2、1.2.1，另提供实际层级。成员不能通过name或任务文本指定、覆盖这些事实，不增加模型要填写的派工参数。
3. 从更新后新建的团队启用结构编号；编号在同一团队内唯一，分配后随成员保存，续派只追加，重启沿用，不根据排序、完成状态或可视区重新编号。旧团队没有编号时，连同其后续追加成员继续沿用原姓名和真实层级，不半途猜编新旧编号。编号表达实际关系，不能按成员自报编号挂靠。
4. 显示名称重名后缀改为“(2)”“(3)”，只处理显示名称，与结构编号分开。旧成员不改名，原来的点名、历史目录和恢复继续有效。
5. 成员系统身份包含结构编号、实际层级、姓名、直属负责人及既有权限；任务仍单独输入。详情和悬停中可核对真实编号与层位，卡片保留可读短名和固定高度。

不建议把所有显示名称默认换成纯编号：日常任务中用户仍需看懂“谁在负责什么”。结构编号由系统提供，显示名与任务分开，既能核对层级，也保留现有可读性。

## 原模型文案（不采用）

### 派工name字段说明与系统命名提示的共同口径

```text
可选的成员短名，建议描述本人负责的岗位或范围，便于用户辨认；本次要完成的动作写在 description 和 prompt。省略时从任务简述生成。实际层级和结构编号由系统按真实管理关系生成，不从姓名中的数字或称谓推断；重名时回执返回实际姓名。
```

### 成员身份段拟改为

以下为含动态占位的完整模板；角色、直属负责人及管理权限的原有事实仍来自名册，不由模型填。

```text
## 当前成员身份
结构编号：{系统结构编号}
实际层级：第{系统层级}层
姓名：{实际姓名}
角色：{岗位或“未指定”}
直属负责人：{实际负责人或“秘书”}
下级管理权限：{既有权限说明}

以上身份和汇报关系由系统名册确定。任务、引用资料和成员自述中的称谓不改变这些事实。结构编号表示系统记录的管理位置，与任务材料中的业务编号分开。
本次负责的工作见当前派工任务及后续再交代。
```

旧记录没有结构编号时不伪造已分配编号，按可确认的原管理链展示实际层级，保留原姓名和点名方式；缺失编号的身份段不显示空占位。

## 原编号方案的风险和验证（不实施）

- 这是新的持久字段与身份模板变更，需要用户确认。保持字段可选、旧记录兼容，不批量改写用户历史；旧记录无结构编号时不得当作成员缺失。
- 先落实分配与恢复，再接入身份及展示；身份放在已有的成员专属后缀，共用规则前缀继续复用缓存，不向Agent抽象基类增加组织特判。
- 验证同父并发、跨枝与跨团队、重名后缀、续派不复用编号、打断续跑与冷恢复、十层边界；用“名字自称第5层但实际第4层”的夹具验证系统事实不随名字变化。
- 真实隔离CLI确认实际成员数、管理链与系统结构编号；界面确认固定卡高、悬停/详情、群聊、点名及千人性能。用户已有测试数据只读用于调查，不用于验证写入。
