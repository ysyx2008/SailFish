# 团队统一入口与透明度（2026-10-30）

已完成，留在 `feat/agent-org` 待验，未合入。用户确认统一称为团队、以全局观察呈现进展/职责/动态产出，干预通过秘书；本轮先实现较轻的统一体验，动态调整组织关系暂缓。

## 范围与实现

1. 复用 OrganizationView 与现有组织图，不引入第三套执行模型。前端从同一任务的 subAgents/expertTeam/organization 构建统一团队视图；组织快照为全貌真相源，分头工作与扁平小组适配为同一树。对话与顶部每个任务一个入口，按真实状态汇总。
2. 复用面板宿主、群聊、产出物预览。成员节点分别显示角色/职责/当前活动，可查看执行过程及结果；成员与小组产出物复用同一查询/预览逻辑。只加载所选成员详情，避免图上千人都读盘。
3. 轻量只读成员详情接口复用现有存盘数据、工具步骤折叠；独立成员成果查询依照真实成员身份，不编造群。历史合并保留原会话来源。新增字段均可选，不改变落盘目录和现有执行行为。
4. 文案对用户统一团队/成员/小组；负责人、验收人仍为身份。成员完成计数不声称项目完成百分比。沿用默认全展开和工作区铺满，不添加图上调度或新设置。

## 验证与风险

聚合覆盖同任务多批、重复追问、旧快照、后续任务隔离；群聊与成果按原会话/负责人/成员隔离，保留原预览草稿行为。验证普通成员、扁平协作组、分层团队三种真实 UI 路径只留统一入口；成员职责与活动、过程、成果、群聊往返与铺满，历史重开及1000人全展开。运行针对性单测、CLI基础回归及不抢前台的隔离UI，独立审查后提交，留 feat/agent-org 待验，不合入。

## 暂缓

改隶属、成员调动、合并重组；token预算/人数额度/固定步数暂停；成果额外归档、版本绑定；任务进度百分比和游戏数值。现有调度由秘书负责，图仅供观察。

## 验证结果（2026-10-30）

- 相关回归 50 文件 / 473 项通过；审查后定向 6 文件 / 25 项通过；最终覆盖来源、完整过程与活动摘要的 13 文件 / 182 项通过。覆盖同任务多批合并、追问去重、原会话隔离、异步切人取消旧请求、30 步完整过程不被两步快照覆盖、成员查询不扫描所有成员和不读模型对话。
- CLI 基础回归 104 通过、3 项真模型检查按 `--no-ai` 跳过。新增 `history:member <会话ID> <成员名>`，验证缺参数报错、找不到成员返回空；正常成员读取由存盘单测和真实 IPC 验证。
- `scripts/ui-e2e/organization.mjs` 与新增 `scripts/ui-e2e/unified-team.mjs` 都通过。三种结构统一入口、职责/活动、个人与小组成果、真实过程、原会话来源、群聊交接、草稿往返、铺满、1000人/101团完整展示均已验证；使用临时数据和不抢前台窗口。
- 已看铺满团队截图，职责与活动分层、默认展开、色彩与返回操作沿用现有界面。Vite 构建通过，修改代码 ESLint 通过。前后端类型检查仍仅有本轮前已存在的 `useAgentMode.ts:1056` 和 `gateway.service.ts:383` 错误；未顺手修改它们。
- 独立审查由本机 Claude CLI 配置的外部模型完成。采纳三处修补：完整成员过程不被最近20步快照覆盖；个人成果标题不误标秘书；统一小组/负责人的残留文案。群聊e2e显式点按钮避免成员点击拦截；原审查会话复核上述问题均已修复。
- 全局活动只携带工具/对象/状态摘要，不复制工具输出正文；成员详情仅选中时异步定位读取。完整旧过程仍可读，无ID的旧运行步骤不猜测合并身份。新增来源与活动字段均可选，没有迁移落盘目录或新增成果保留机制。
- 按只读数据支持、统一界面两步追加提交；已交验分支不改写历史，develop上的后续变动留合入前同步和复验。

## 用户验收

先退出旧验收进程，再运行 `review agent-org`。可直接打开已有团队检查：对话和顶部统一入口，点成员看职责/活动/过程/个人成果，点小组看群聊/成果，铺满后往返。无需再生成千人任务。

轻量新任务提示词：

> 请安排两位成员分头各写一份简短说明，说明自己负责什么，并将结果写到临时工作目录。不要再派下级成员。

检查两位成员共用团队入口、各自职责和成果可见；所有安排通过秘书，不出现拖拽调动或改隶属操作。
