# 你话里提到的人，秘书自动认出来

> 落盘：2026-10-14 · 状态：已完成（2026-10-14）

## 要解决的问题

联系人现在是「用到才查」：要靠秘书自己判断去搜。它常常不搜，直接接一句「好的，我联系一下王总」，表现得并不认识这个人。整本名单每轮带上又太占地方，人越多越贵。

用户提议（2026-10-14）：自动匹配用户消息里的联系人名字，找到了就把这个人的信息带给模型，秘书就会表现得像认识他。讨论结论：短简称也要认——会用短简称叫的正是熟悉、常来往的人，联系人里记下的简称本来就是用户平时怎么叫这个人。

## 用户能感知的样子

- 你在任务或联络里说「帮我约一下梁总下周见面」，秘书这一轮就知道梁总是火山引擎管采购的那位、邮箱是什么，直接接着办，不用先去查。
- 简称、全名、邮箱、电话都认。「老王」「沈总」这种两个字的简称照样认。
- 同名的几位一起带上：「王瑜」对上火山引擎和国元证券两位，秘书自己分辨，分辨不了就问你是哪位。
- 一句话里提到很多人（比如贴了一长段邮件），只带前 5 位，其余只报名字，秘书需要时自己查。
- 同一场对话里已经带过、信息又没变的人，后面再提不重复带；你或秘书改过这个人，下次提到时带新的。
- 秘书自己在后台跑的关切、唤醒不带；派出去的伙计不带；联系人技能关掉时不带。
- 界面上你的那句话照原样显示，名片只给模型看。

## 不做

- 秘书自己的回复、工具读回来的网页和文件里出现的名字不认，只认你说的话（含你贴进来的文字）。
- 不按意思猜「他」「那个销售」指谁。
- 一个字的简称不认（一个字太容易出现在别的词里；正常也不会只记一个字）。

## 带给模型的样子（提示词，请审）

附在你这句话旁边、和「你刚才主动发过什么」等背景放在一起：

```
这句话里出现的名字或联系方式，联系人里记着：
- 梁晓东〔联系人 c-liang〕人 · 火山引擎 · 采购负责人；简称：梁总；邮箱 liangxd@volcengine.example；备注：对接大模型采购，喜欢先看报价再约会
- 王瑜〔联系人 c-wy-a〕人 · 火山引擎 · 销售；邮箱 wangyu@volcengine.example
- 王瑜〔联系人 c-wy-b〕人 · 国元证券 · 投行部经理；邮箱 wangyu@gyzq.example
另外还提到：张三、李四（未展开，contact 技能里可查）
```

（实现后的实际样子：编号是完整联系人编号；「可查」处写技能名而非工具名——技能没装上时模型看不到 contact_search，但技能清单里有 contact。）

- 只陈述「联系人里记着什么」，不写「请据此回答」之类的指示。
- 备注截到约 120 字，后面加省略号。
- 编号让秘书能直接用 contact_update 改这个人。

## 技术方案

### 认人（contact 模块内，新文件 `skills/contact/mentions.ts`）

- 从 `ContactBook.list()` 建索引：每人的姓名、简称（规范化后），邮箱、电话（规范化同 `findPossibleSamePeople`）。
- 名字匹配：
  - 键长不足 2 个字符的跳过。
  - 含中日韩文字的键：在消息里直接找子串。
  - 纯拉丁字母 / 数字的键：大小写不敏感，前后不能紧挨字母数字（「Al」不认「also」里那段）。
  - 整段落在更长一段里面的不单算：「沈义君」认出来了，落在这段里面的「义君」不再单独算。只是交叠（「张伟明」里的「张伟」「伟明」）的两段都算——分不清就都带（代码审查后从「重叠取长」改成「包含才丢」）。
- 邮箱：消息里按规范化后完整出现即认，句末的点不碍事。电话：消息里的数字串（可用空格、横线分段，不跨行）去掉分隔后与记下的电话一致即认（不少于 7 位）；带不带国家码都认——两边都 ≥11 位、长度只差 ≤3 位时比后 11 位，长流水号尾巴恰好一样不算。
- 按在消息里首次出现的位置排序；超过 5 位的只报名字。
- 去重（实现与草案不同）：不另造版本标记，名片本身就是确定性的——同一个人、信息没变时写出来一字不差，名片覆盖了联系人的全部可变字段。调用方传入「这场对话当前消息里（含本轮已收的补话）是否已有这段文字」的判断，已有就跳过。交接/压缩/重启把旧名片收掉以后自然会重新带。已知取舍：备注截断在 120 字，之后的部分改了不会触发重带。

### 抽象层不认识联系人（OOP 边界）

- `skills/types.ts` 的 `Skill` 加一个可选钩子：`noteForUserMessage?(text, ctx) => string | undefined`，含义是「用户说了这句话，这个技能有没有要附带给模型的背景」。和现有的 `onRunStart` / `wrapToolCall` 不同，它**不要求技能已装上**，只要技能开着就会被问——联系人平时不装，但该认人。
- `skills/index.ts` 加 `collectUserMessageNotes(text, ctx)`：遍历开着的内置技能（`BuiltinSkillEnablement`），收集各自的附注。
- `agent.ts` 只调这个通用入口，不出现联系人字样：
  - `buildUserMessage`：非伙计、非内部通知、会话是任务或联络时，把附注放进 `systemContextParts`。
  - 运行中补话（`processPendingUserMessages`）：同样条件下把附注拼进补话那条消息。
  - `ctx.alreadyInConversation(text)`：扫当前这场的消息内容。
- 「哪类会话附」进 `CONVERSATION_POLICY` 的 `skillNotesOnUserMessage`（task / companion 开，watch / wakeup 关），不在 agent 里写 kind 判断。
- `collectUserMessageNotes` 在 `skills/user-message-notes.ts`，每个技能单独 try/catch，一个出错不连累别的。

### 文档

- 联系人 SPEC：「用到才查」一条改写为「提到谁带谁」（见下）。
- agent SPEC：技能可以「旁听」用户的话、附带背景，技能没装上也会被问。
- project-architecture：技能钩子一句补上。

联系人 SPEC 改写草稿：

> **提到谁带谁**：联系人不进心跳，也不整本带上。你在任务或联络里说的话里出现了某个联系人的名字、简称、邮箱或电话，秘书这一轮就会看到这个人记着的信息，像认识他一样接话。记下的简称就是你平时怎么叫这个人，再短也认，只有一个字的不认。同名的几位一起带上，由秘书分辨或问你。一句话里提到太多人只带前几位，其余只报名字。同一场对话里已经带过、信息没变的不再重复。只认你说的话；秘书在后台跑的关切和唤醒不带。
