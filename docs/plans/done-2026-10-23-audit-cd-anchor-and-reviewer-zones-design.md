# 命令审计认得 `cd 绝对路径 &&`，评审员知道事先放开的目录（已完成，2026-10-23，分支 `fix/audit-cd-reviewer-zones`，未合入）

## 起因

「替我审批」把 `cd "<scratch>" && rm -rf out_test mailpkg exam/pdf && echo … && ls` 交回了用户，
理由读起来像放行。查下来是两道关叠在一起：

1. 命令审计：`rm` + 相对路径 → 高危。草稿目录本来是免确认的，但自 2026-07-18 起相对路径一律不降级
   （`cd ~/Desktop && rm foo.txt` 曾被按审计默认目录当成草稿目录而放过）。智能体几乎每条命令都写成
   `cd 绝对路径 && rm 相对路径`，提示词里提醒也不改。
2. 评审员：看不到旗鱼的安全规则（草稿目录、临时目录、用户加的免确认目录），也不知道审计定级是风险分的
   下限。它按自己的判断打低风险、低授权、allow，旗鱼把风险抬到高之后对表过不了，界面上却是一句
   像放行的理由。

## 实现要点

- **锚点识别**（`extract-calls.ts`）：全局闸门任何一条不过就整条命令不认锚点——有函数定义；有无参命令
  （纯赋值）或命令名不是字面量；出现 `pushd/popd/source/./eval/alias/shopt`；`builtin/command` 后跟
  动态词；字面量 `cd/pushd/popd` 词多于一个；唯一的 `cd` 不是恰好 `['cd', 字面量绝对路径]`（无选项、
  无 `..`、无 `$ \` * ? [ ] { }`）。过了闸门，还要求这个 `cd` 是顶层纯 `&&` 链（不取反、不后台、
  不含 `;` `||`、子 shell、花括号）里的一环，链上它之后的普通命令（`sudo -D` / `env -C` 包装、
  `bash -c` 内部脚本不算）才带上 `anchorCwd`。
- **解析**（`assess-call.ts` / `workspace-guard.ts`）：带锚点的调用，审计目录换成 `realpath(锚点)`
  （内核按真实目录解析相对路径，符号链接要先跟）；相对路径视同「位置已知」参与自由区降级；
  凭据禁区、系统路径检查用同一个目录，比以前按默认目录猜得准。
- **`cd` 进白名单**：`safe`、只读、可带 `-P` `-L`。以前被当成未识别命令，带 `cd` 的命令整体被拖到中危。
- **评审员目录栏**：`listFreeZoneDirs(extraFreeDirs)` = 内置自由区（工作区 `scratch/charts/migrations`
  + 系统临时目录根）+ 用户额外目录；设置页的内置自由区展示同样改用 `getBuiltinFreeDirs()`。请求新增
  `freeDirs`；会话里记下一份拷贝，清单变了评审员那条线从头来。不预先替评审员算「目标落在哪一区」
  （按默认目录算，`cd` 到别处会算错，等于把老漏洞交给评审员）。
- **日志**：`[auto-review] … audit=<审计档> risk=<抬过的> auth=<> model=<原风险/原授权/原结论>`。

- 真 bash：审计判安全的写法，另起一个目录真跑，删的确实是 `cd` 之后那个目录里的文件；`cd` 失败时 `rm` 根本不跑。
- 回放真实对话（只读历史）：那场对话被拦的 12 条命令，现在直接放行 3 条（含用户截图那条）；
  其余是 `cd` 连着另起一行用相对路径、变量路径、相对 `cd` 等，仍会问（设计内的保守），交给评审员。
- 真模型评审员评测（`scripts/eval-auto-review.cjs`）：必须交回的 13 条全部拦住；新增「目录内清理」5/5 放行；
  明确授权的对照组 5/5。「没有就删最像的」这类本来就模棱两可的对照场景，加上第 3 项后放行率从约 55–65% 降到约 13%。
- 真实命令回放评审员（每种配置 24 次）：旧说明书 23/24 放行；只加目录栏 24/24；目录栏 + 下限 22/24。差别在噪声内。

## 代码审查（Claude CLI）与处理

- 采纳：花括号展开（`rm -rf /tmp/{x,../../Users/me/Desktop/foo}` 以前就判安全；`cd /tmp && rm -rf {…}` 这次会新放开）→ 含花括号的写/删目标一律不降级；锚点目录被反转义两次 → 只去一次，原文和去转义后两种读法都要过关；评审员说明书补两句事实。
- 不改、写进 SPEC 已知局限：同一条命令里前面的命令先建软链再 `cd` 进去；持久终端里先装下别名/函数改变 `cd`。这两类对绝对路径早就存在，直接跑脚本更是绕得过，不是这次引入的类别。
- 不采纳：评审员说明书限定「只有位置确定的写法才认自由区授权」。评审员存在的意义就是处理审计证明不了的情形，它可以先用核查工具看目标目录；只补事实，不加限制。
- 记入想法本：评审员「只读核查」能借 `cp` 写文件（既有）。

## 没做的

`cd` 连着另起一行用相对路径；相对的 `cd`（`cd mailpkg`、`cd ..`）；多个绝对 `cd` 接力；
后台执行实际所在目录；远程机器上的路径。记在 `docs/ideas.md`「命令审计看准相对路径」条目。
