# 档案室文件改名（秘书与设置里都能改）

状态：**未完成（暂缓）**（2026-10-18 落盘；同日讨论后用户定为先不做）

没有写进 SPEC：设计取舍没有最终确认。讨论过程留在这里，以后要做时从这里接着。

## 讨论结论（2026-10-18）

- 直接改文件名有两个问题：文件名是原件的名字，改了就和磁盘上的原件对不上；同目录再放同名文件会替换旧版（换版），改名后重放会变成多出一份。
- 更合适的形态是「显示名」：原始文件名保留不动（换版、溯源仍靠它），秘书和用户改的是显示名；列目录、搜索结果、自动带入的标题、名字相似度都用显示名；文件详情里同时列出只读的原文件名；同目录显示名不能重复。工作量与下面的方案相当，多一个可选字段。
- 用户的档案里名字乱、对不上的文件只是少量，检索说明已能补标题表达不了的问法，所以先不做。

以下方案是直接改名版，若以后做，需改成上面的「显示名」形态。

## 现状

- 档案室文件的名字存在文档索引里（`filename`），另有两处副本：向量库和词索引里每个片段各带一份，名字相似度另有独立的一条（`fileNameKey(docId)`）。
- 秘书的整理工具有建目录、挪文件、目录改名、删目录，没有文件改名；设置里文件详情有「挪到目录」，没有改名。
- 片段里的那份名字只在展示时被读出来（搜索结果标题、自动带入的标题、CLI 输出），不参与检索。

## 做法

不去改向量库、词索引里每个片段的名字（要整份重写，且正是 SPEC 里说的「改一个名字只改一条」要避免的）。展示时以文档索引里的名字为准，片段里留着的旧名字不再被读出来。

| 位置 | 改什么 |
|---|---|
| `knowledge/catalog.ts` | 新增文件名校验（去首尾空白、不能为空、不含 `/` `\`、长度上限），出错沿用目录那一套的错误类型 |
| `knowledge/index.ts` | 新增 `renameLibraryDocument(docId, name)`：只对档案室文件；同目录同名拒绝；改索引里的名字、更新时间不变动内容；补一次名字相似度；不碰片段、不碰说明（说明的来源哈希只看原文）。搜索结果出口统一用索引里的名字覆盖片段里的旧名字 |
| `agent/skills/archive/{tools,executor}.ts`、`agent/i18n.ts` | 新增 `archive_rename`（doc_id、name），说明里只写事实：只改名字、同目录重名不改、不用确认 |
| `agent/tools/knowledge.ts` | 搜索结果标题改读新名字（走服务出口，不自己拼） |
| `electron/main.ts`、`preload.ts`、`vite-env.d.ts` | 新增 `knowledge:renameDocument` IPC |
| `src/components/Memory/MemoryPanel.vue` + i18n（zh/en） | 文件详情底部加一行「文件名 [输入框] [改名]」，与「目录 [输入框] [挪动]」同一排样式；改完刷新并重新选中 |
| `electron/cli/index.ts` | `knowledge:rename <docId> <新名字>`，便于端到端 |
| 测试 | 服务：改名成功、同目录重名拒绝、非法名字拒绝、搜索与列目录显示新名、说明不作废、其他目录同名允许；技能：工具走通；面板：改名后显示新名；CLI 回归加一条 |

## 风险

- 片段里残留旧名字：只要展示出口全部走索引名就看不到；新增出口时要记得走同一处。已查现有出口：搜索结果标题（服务、秘书工具、CLI）。
- 重建索引（repairIndex / 重建）会从文档索引里取名字重新写入片段，改名后重建会自然带上新名字。
