# 扫描版 PDF 页面图默认不摊开（只在助手调试模式下显示）

> 状态：**已完成**（2026-10-18 落盘并完成）
> 设计目标：`src/components/AIPANEL_SPEC.md`「发出去的消息就是用户发的样子；扫描版 PDF 的页面图默认不摊开」（已写入，含 IM 一条）
> 想法本：`docs/ideas.md`「发出去的扫描版 PDF，下面挂页面缩略图可能多余」

## 现状（为什么不是改一处 CSS）

- 发送时，页面图和用户自己贴的图被拼成**同一个数组**（`previewImages = [...用户图, ...PDF 页面图]`），随后一路当「气泡里要显示的图」往下传，最后落进 `user_task` 步骤的 `images`。到了渲染那一层，两种图已经分不开了。
- 这个数组经过的地方很多：首发、补话（`user_supplement`）、排队（`followUpQueue`）、没送达放回输入框（`handBackUndelivered`）、队首合并（`follow-up-drain`）、乐观上墙与后端步骤对账（按图的张数比）。
- 历史落盘时，只有 `step.images` 会被外化成磁盘文件；加载历史时 `terminal.ts` 用**逐字段白名单**重建步骤，不认识的字段会被悄悄丢掉。

所以「藏页面图」必须先让页面图有自己的位置，不能在渲染时去猜哪几张是页面图（按位置、按张数猜都会在补话合并、Word 内嵌图混入时错位）。

## 方案

给页面图单独一个字段 `docPreviewImages`，和用户自己的图（`images` / `previewImages`）从发送端起就分开走：

1. **发送端**：`getPreviewImages` 只返回用户自己贴的图；PDF 页面图另走 `getDocPreviewImages`，新字段随同一批请求发出。`images`（给模型的全量图）不变，模型照样拿到全部页面。
2. **后端**：建 `user_task` 步骤时把新字段写进步骤；历史外化把它和 `images` 一样处理，不让 base64 内联进会话 JSON。
3. **加载历史**：`terminal.ts` 的白名单（以及后端 `stepToStepRecord` / `stepRecordToStep`）加上新字段。
4. **渲染**：任务分组把新字段带到 group；`AiPanel` 只在 `agentDebugMode` 打开时渲染它，「仅预览前 N 页」提示同样受这个开关管；用户自己的图照常显示。图片画廊的收集同步：关着时不收。
5. **老消息**：没有新字段，页面图仍混在 `images` 里，保持原样显示（与设计目标第 5 条一致）。
6. **约定**：`previewImages` = 气泡里显示的用户自己的图，空数组表示一张都不显示，**不要退回显示 `images`**；`docPreviewImages` = 页面图。所有路径（新任务、补话、run 开始前缓冲的补话、排队 / 插入当前对话、交接、IM）都按这个约定。
7. **补话**：中途补话（`user_supplement`）在调试模式下也能显示页面图，所以补话路径同样带新字段（计划里原写「不为它加字段」，实现时改为加，行为才一致）。

### 不动

- 页面怎么渲、渲几页、发给模型的内容。

## 决定

- IM 渠道（钉钉 / 飞书等）：**一起收掉**，行为统一。IM 联络气泡里不再挂页面图（Word 内嵌图原来在补话气泡里会显示，现在也不显示，与新任务一致）。

## 已知小局限

- 交接来的排队项（一轮结束时没吃进去的补话）再被点「编辑」放回输入框时，页面图会当作用户贴的图一起放回来，保存后会显示在气泡里。这种项没有文档对象可还原，且编辑前后模型拿到的内容不变；暂不处理。
