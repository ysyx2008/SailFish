# 输入框图文混排：文件和图片成为文字里的胶囊（方案）

状态：未完成（2026-10-18 方案已确认；第一步「换底座」代码已完成并自测，等用户真机验收；第二步未开始）

想法本条目：「拖进输入框的文件变成文字里的胶囊」。设计取舍已写入 `src/components/AIPANEL_SPEC.md`「文件拖进输入框，成为文字里的胶囊」。本文只写怎么做。

## 起因

现在输入框里文本是文本、附件是附件：文件、图片在文字上方排成独立一行，发出去时模型收到「一段文字 + 一堆附件」。用户写「把这个改成那个」，「这个」指哪个文件，输入框和模型都无从知道。希望文件落进文字里，成为句子的一部分。

## 现状（读代码得到的事实）

- 输入区是一个纯 `<textarea>`（`AiComposer.vue`），`inputText` 字符串是唯一真相；斜杠命令高亮靠叠一层镜像 div，`@` 菜单靠 `useMentions` 在 textarea 上读光标位置。
- 附件不在文本里：图片在 `pendingImages`，文档在 `uploadedDocs` / `parsingDocs`，由 `useImageUpload`、文档上传 composable 管，`AiPanel` 发送时把它们和文字拼成 `images` / `attachments` / `documentContext` 一起交给后台。
- 草稿、排队消息、没送达放回，都是「文字 + 图 + 文档」三份分开存取（`terminalStore` 草稿、`follow-up-drain`、`restoreDraftMedia`）。
- 输入框被欢迎页（`WelcomeChatComposer`）和对话面板（`AiPanel`）共用，另有「文档铺满」的薄胶囊形态。
- 项目里没有现成的富文本编辑器依赖。

## 做法

两步，分开验收（重构与新功能分开）。

### 第一步：换底座，行为不变

把 `<textarea>` 换成能在文字中间放行内块的输入元素，文件和图片仍照旧显示在上方，外观和行为与现在一致。

- 编辑器选型：自己用 `contenteditable` 写一个薄封装，还是引入 TipTap / ProseMirror。**倾向引入成熟库**——输入法组合输入、撤销重做、粘贴净化、光标在行内块两侧的行为，自己写容易反复出 bug。选型要用户确认（新增依赖）。
- 对外保持现在的接口：取文本、设文本、聚焦、追加文本（语音输入用）、光标位置（`@` 菜单用）。外面的代码（`AiPanel`、`WelcomeChatComposer`）尽量不动。
- 必须逐项对一遍不变：回车发送 / 排队键 / Shift+回车换行、输入法组合中不触发发送、`@` 菜单（文件 / 文档 / 技能）、斜杠命令高亮与 Tab 补全、占位符随机池、自动增高到两行再滚动、粘贴（文本优先、无文本才当附件）、草稿保存恢复、语音追加、编辑排队消息、没送达放回。
- 斜杠命令的镜像层随之去掉，高亮改在编辑器里直接渲染。

### 第二步：文件、图片落进文字

- 拖放：胶囊落在松手位置（编辑器能由坐标求出文字位置）；点加号选文件、粘贴文件：落在光标处。多个文件依次排在同一处。
- 胶囊样子：文件 = 图标 + 文件名（解析进度沿用现有那根底边细线与页码）；图片 = 小缩略图 + 文件名，点开仍是现在的大图预览。出错（解析失败、图太大）留在原位带警告，与现在一致。
- 删除：光标紧贴胶囊时退格，先选中，再退格才删（防误删）；胶囊上也有叉。
- 发送：把输入框内容读成有顺序的「文字 + 附件」序列，胶囊在文字里的位置转成一段客观标记（如「[附件：报价.xlsx]」），文字照常发给模型；`images` / `attachments` / `documentContext` 仍按现在的方式随消息发出，后台与历史不用改格式。标记写法属于给模型看的文案，按「客观中性描述」原则，只描述「这里是哪个附件」，不写指令。
- 对话气泡：先不动（附件仍显示在气泡下方）；气泡里也混排是后续独立事项，不在这次。
- 草稿 / 排队 / 放回：文字里带着标记，附件仍存各自的列表，恢复时按标记把胶囊放回原位；标记对不上附件（附件已被删）时，退化为普通文字。

## 用户已确认（2026-10-18）

1. 编辑器：引入成熟库。选用 TipTap 的核心（`@tiptap/core` + 文档/段落/文字/撤销/占位文字扩展），不用 Vue 封装层，自己在 `ComposerEditor.vue` 里挂载。
2. 图片：这次不做，先做文件；图片仍是单独一排。
3. 引用片段、技能胶囊：不动。
4. 退格对胶囊：先选中，再按一次才删。

## 第一步实现备忘

- 编辑区对外仍像文本框：带换行的纯文本、纯文本偏移光标；`@` 菜单、斜杠命令、草稿、发送都没改成别的模型。
- 外部改文字（发送清空、场景卡片填入、没送达放回）整份换掉，撤销历史清空，光标放文末，与原来给文本框赋值一致。
- 发送键、菜单导航由外层 keydown 先处理，处理了（`preventDefault`）编辑区就不再换行；粘贴先交外层（图片/文件当附件），其余只收纯文本；拖入文件编辑区不处理，留给外层拖放。
- 斜杠命令名高亮改为编辑器内的行内装饰，去掉叠在文本框上的镜像层；高度改为自然增高（上限 360px，欢迎页 160px），不再手工测量。

## 风险

- 输入法组合输入与行内块混用，是富文本输入最容易出问题的地方；第一步单独验收就是为了把它隔离出来。
- Windows 与 macOS 的拖放、IME 表现不同，真机至少两个平台各过一遍。
- 「文档铺满」薄胶囊形态与新编辑器的高度自适应需要一并核对。
