# 联系人面板（秘书菜单 → 联系人）

> 落盘：2026-10-14 · 状态：已完成（2026-10-14）

## 要解决的问题

联系人结构化以后，用户只能问秘书才知道记了什么；秘书记错、记重（例：梁总、刘玲玲被写进两家公司的备注，没单独成人）用户发现不了。用户认为联系人也算重要，希望像待办一样随手能打开。

2026-10-14 讨论：「像待办一样」只做入口这一层——和待办同在秘书菜单、打开占主区域。不挂计数、不提醒；秘书平时不带名单（第三层）、从联系人直接让秘书找人办事（第四层）另记想法本。最初想放在设置里知识库旁边，讨论后改到秘书菜单：设置是调软件的地方，弹窗也窄。

## 用户能感知的样子

- 秘书菜单里「待办」下面多一项「联系人」，没有角标。点开后联系人面板占主区域，和待办面板同样的打开 / 关闭方式。
- 面板头：标题、共几位、「新增联系人」按钮、关闭。
- 搜索框，按姓名 / 简称 / 单位 / 角色 / 邮箱电话搜（与秘书查人同一套匹配）。
- 列表，每行：姓名（机构带标记）、简称；副标题是单位 · 角色 · 第一个联系方式。点一行在原处展开编辑。
- 编辑：姓名、简称（逗号分隔）、人 / 机构、单位、角色、联系方式（逐条：邮箱 / 电话 / 即时通讯 + 值 + 平台，可增删）、备注。底部：保存 / 取消；「删除」（确认）、「合并另一条进来」（选一条，确认后并入，那条删除）。
- ~~保存时姓名或简称与别人撞了：不保存，说清和谁撞了，提示可以合并。~~ 2026-10-14 用户：「同名很常见」，改为允许同名——新增时已有同名的列出来（带单位/角色），可打开那条或「是另一个人，照样新增」；改名、合并不拦。秘书新增时姓名/简称或邮箱/电话一样的先返回候选，确认是另一个人（`different_person: true`）才建。
- 秘书那边改了联系人，列表自动刷新；正在编辑的那条不被冲掉，只提示「这条刚被改过」，用户手上的改动先不存，接着改或关掉详情才用他的版本覆盖。
- 技能关掉时面板照常能看能改（数据还在）。

### 合并规则

当前这条保留：姓名、人 / 机构不变；被并那条的姓名和简称都成为当前这条的简称；联系方式取并集去重；单位、角色当前这条空着才补；备注两段不同就上下拼起来；创建时间取早的。被并那条删除。

## 本次不做
