# 编程工作台方案

> 落盘日期：2026-09-26
> 状态：未完成（暂缓）——2026-09-26 用户：先不考虑编程，在想是不是另外发布一个软件而不是集成进旗鱼。
> 来源：`docs/ideas.md`「专门的『编程』工作台」
> 本文是讨论稿。§1 是已和用户对齐的设计目标，开工前先搬进 SPEC（去掉实现名）；§7 是还没拍板的问题。

## 1. 已对齐的设计目标

- **定位**：让秘书更好地接手编程活，不是做 IDE。现在也能干，但干不好，主要是缺趁手的工具。Cursor、Claude Code 也在淡化 IDE，方向殊途同归。
- **和现成编程 agent 的关系**：替代它们完成不太复杂的编程任务，不是去指挥它们。
- **工具只在编程台出现**：像人要编程就开 IDE，不再用记事本。普通助手、终端页看不到这些工具，也不因此变重。
- **一个编程台绑一个项目**：进门先选项目目录，这场对话就在这个项目里干活。
- **第一版只做本机**，远程以后再说。
- **第一版六类能力一次做全**：看得懂、改得准、能自证、git、给人审、懂项目规矩。
- **看得懂必须有结构理解**：大项目只靠搜索不够，要有 Visual Studio 类浏览器那样的工具——这里有什么、怎么连着，包括查函数引用。现成的 CodeGraph 太大，不内置，自己做轻的。
- **不压到不写代码的人**：编程台的重东西按需下载、只在编程台开着时运行；不开编程台的人感觉不到它存在。

## 2. 现状摸底

| 项 | 现状 | 对编程台意味着什么 |
|---|---|---|
| 工具开关 | 只按 `AgentMode`（local/ssh/assistant）过滤，`_meta.supportedModes` | 后端不知道自己在哪个工作台，得加一道「按工作台」的门 |
| 工作台声明的 skills | `WorkbenchDescriptor.skills` 只在 bootstrap 收集、打日志，没接通 | 不能靠它挂工具；且技能是「按需加载」，不是「进门就有」 |
| `WorkbenchKind` | 定义在 `packages/workbench-sdk/src/types.ts`，前端独有 | 后端要按它过滤工具 → 挪进 `@sailfish/shared-types`，保持唯一真相源 |
| 前端→后端的工作台信息 | 只有 `workbenchPrompt`（字符串）和 `workbenchContext`（选区袋） | 要多带「工作台类型 + 项目根」 |
| 内容搜索 | 没有工具；`file_search` 只搜文件名（系统索引），描述里让模型「用 grep」即走 `exec` | 需要项目内、认 `.gitignore` 的内容搜索 |
| 代码结构 | 无（依赖里没有 tree-sitter / LSP） | 需要新引入 |
| 修改 | `edit_file` 单处查找替换；`write_text_file` 多模式 | 缺一次多处、跨文件的原子修改 |
| 撤回 | 无任何文件检查点/撤回机制 | 需要新做，也是「项目内改文件能否免确认」的前提 |
| 自检 / git | 只能 `exec` 裸跑，输出原样灌回 | 需要结构化、截断到「有用的那部分」 |
| 画布 | 助手工作台一次一个座位：空 / 终端 / 文件；产出物清单 | 「改动」可以作为新的一类入座内容 |

## 3. 地基：编程台是什么、工具怎么只在这里出现

### 3.1 形态

- `TerminalType` **不加新成员**：编程台操作的仍是本机，形态仍是 `assistant`（本机助手，可以请终端入座）。
- `WorkbenchKind` 加 `'coding'`，和 `companion` 一样是「`tab.type='assistant'` 但工作台不同」的一类，经 `resolveWorkbenchKind(tab)` 这个唯一映射点识别。
- tab 上记 `projectRoot`（绝对路径），进门选定后这场对话内不变。

### 3.2 后端知道自己在编程台

- `AgentContext` 增加 `workbenchKind?: WorkbenchKind`、`projectRoot?: string`（由 `useAgentMode` 发起 run 时带上）。
- `WorkbenchKind` 挪到 `@sailfish/shared-types`，`workbench-sdk` 改为 re-export。
- 编程台内：工作目录钉在 `projectRoot`；相对路径按项目根解释（顺带让命令审计拿到真实起始目录——想法本「命令审计看准相对路径」的一部分在这里天然成立）。

### 3.3 工具的门

- `ToolMeta` 加 `workbenches?: WorkbenchKind[]`：声明了就**只在这些工作台出现**；没声明的照旧（对所有工作台可见，仍受 `supportedModes` 约束）。
- `GetAgentToolsOptions` 加 `workbenchKind`，`getAgentTools` 在按 mode 过滤后再按工作台过滤。
- 子 Agent（`dispatch_agents`）在编程台里继承同一套编程工具（读类全给，写类按现有子 Agent 规则）。

### 3.4 会话与历史

- 编程会话落盘时记下「编程台 + 项目根」，和 `terminalType` 一样创建后不可变。
- 从历史点开编程会话：回到编程台、同一项目续聊（同形态漫游）。不在普通助手里续——否则工具没了，模型会凭记忆去调不存在的工具，这和「跨形态不漫游」是同一个理由。
- 项目目录不在了（被删、被挪）：说明白，让用户重新指定或只读查看。

## 4. 六类能力

### 4.1 看得懂

| 工具（暂名） | 做什么 | 实现要点 |
|---|---|---|
| `code_search` | 项目内按内容搜（正则 / 字面），带上下文行，结果有上限 | 打包 ripgrep 二进制（`@vscode/ripgrep`），子进程跑，认 `.gitignore` |
| `list_files` | 项目内按模式列文件（`**/*.ts` 之类） | 同上，`rg --files` |
| 类浏览器（见下） | 这里有什么、它们怎么连着 | 结构索引引擎，见下 |
| 项目概览 | 进门时给模型一张「仓库地图」：目录骨架 + 主要文件的主要符号，按 token 预算裁剪 | 复用结构索引；注入 system prompt，不是工具 |

**类浏览器**（2026-09-26 对齐：大项目只靠搜索不够，要像 Visual Studio 的类浏览器那样，包括查函数引用；用户自己装 CodeGraph 也是为了这个）：

- 能问的：某个目录 / 文件有哪些类和函数（大纲）；某个类有哪些成员、继承谁、被谁继承；某个符号的定义原文；谁引用 / 调用它、它调用谁；改了它会波及谁。
- 搜索回答「这串字在哪」，类浏览器回答「有什么、怎么连着」。两者都要，各管各的。

**引擎：自建，不内置 CodeGraph**（2026-09-26 对齐：CodeGraph 太大，不适合内置）。

CodeGraph 单平台约 190MB，拆开看（本机 1.2.0 darwin-arm64 实测）：

| 部分 | 大小 | 自建时 |
|---|---|---|
| 自带 Node 运行时 | 115MB | 省掉：用 Electron 自带的 Node（utilityProcess / `ELECTRON_RUN_AS_NODE`） |
| 解析底座 `web-tree-sitter` | 约 1MB | 要 |
| 各语言语法（wasm） | 每种 0.5–5MB，全套约 60MB（TS+TSX 约 4.6MB，C++ 4.5MB，ObjC 7.5MB） | 按项目用到的语言按需下载 |
| 其余（索引库、提取逻辑等） | 十几 MB | 自己写 |

分两层：

1. **基础层（所有语言，第一版做）**：tree-sitter 语法解析 → 大纲、类成员与继承、定义原文、调用关系、按名字跨文件认引用（排除注释和字符串）、波及面。准确度是「大多数时候对，同名会混」，工具结果里标明「按名字认的」，让模型对关键结论自己核一下。
2. **精确层（以后做）**：项目自带编译器 / 语言服务时借它精确查引用。TypeScript 项目基本都有自己的 `typescript`，用项目那份，旗鱼不多装。每种语言各接各的，所以放到后面。

实现要点：

- 索引存旗鱼数据目录（按项目分），不往用户仓库写任何东西。
- 首次建全量索引，之后监听文件变动增量更新；agent 自己改完文件立即更新那一个文件，不等去抖。
- 索引存储：依赖里没有 SQLite；先确认 Electron 37 自带 Node 的 `node:sqlite` 能否直接用，不行再选内存索引 + 按项目落盘。
- 解析、建索引一律在子进程里跑，不进主线程；建索引期间工具照常可用，结果注明「索引尚未建完」。
- CodeGraph 不内置，但用作**对照尺子**：验收时在本仓库上拿两边结果比，看漏了多少、认错了多少。
- LSP 第一版不做（精确层以后可能走它，也可能走各语言编译器的 API）。

**重东西的原则**（2026-09-26 对齐：担心软件做得太重）：

- 编程台的重依赖（ripgrep、结构索引引擎）按需下载，不进安装包；不开编程台的人装包体积、启动速度、内存都不受影响。
- 只有编程台开着时才起索引、拍快照；关了就停。
- 编程台整体放在独立的工作台包里，不往主干渗。

### 4.2 改得准

- `multi_edit`：一个文件里一次改多处，全部匹配才落盘，任何一处对不上整次不改。
- `apply_patch`：跨多个文件的一次改动（新建 / 修改 / 删除 / 改名），同样全成或全不成。
- 改完在结果里顺带回报这个文件的**语法错误**（tree-sitter 解析即得，毫秒级），不等跑完整检查。
- `edit_file` / `write_text_file` 在编程台里照旧可用。

### 4.3 撤回（改得准的兜底，也服务于「给人审」）

- 影子仓库：`userData` 下每个项目一个独立 git 目录（`--git-dir` 指过去、`--work-tree` 指项目），**不碰用户自己的 `.git`**。
- 每一轮任务开始前拍一次快照；这一轮结束后可以「撤回这一轮」。快照看的是整个工作区，所以 agent 用命令改的文件（比如跑了格式化、代码生成）也能撤。
- 快照认 `.gitignore`，不拍 `node_modules` 之类；超大项目要有上限和降级说明。

### 4.4 能自证

- 进门时识别项目的检查和测试命令（`package.json` scripts、`tsconfig`、`pyproject`、`Cargo.toml`、`go.mod` 等），识别结果给用户看、可改，按项目记住。
- `run_checks`：跑类型检查 / lint，只回报错误清单（文件、行、信息），截断、去重。
- `run_tests`：跑全部或指定的测试；长的走现有后台执行 + 等待；只回报失败的用例和关键输出。
- 编程台提示词里写明工作方式：先搜、再读、再改；改完自检；检查不过不算完。

### 4.5 git

- 读类（`git_status` / `git_diff` / `git_log` / `git_show`）：结构化输出，不确认。
- 写类（提交、开分支、切分支、暂存）：走现有确认规则。
- 推送、强制类操作（`push`、`reset --hard`、`push --force`、改历史）：见 §7。

### 4.6 给人审

- 画布上多一类入座内容「改动」：列出这一轮（或这场对话）改过的文件，每个文件看改动前后对比。
- 可以整个文件或一块一块地打回：打回就是把那块在磁盘上还原，并告诉 agent「用户打回了这几处」。
- 只读查看，不做编辑器；人要手改就用自己的编辑器（可以给一个「在外部编辑器打开」）。
- 画布规则沿用助手工作台 SPEC：一次一个座位，终端入座坐左边，文件和改动是参照、坐右边。

### 4.7 懂项目规矩

- 进门自动读入项目里的开发约定：`AGENTS.md`、`CLAUDE.md`、`.cursor/rules` 下总是生效的那几条等，有预算上限，超了截断并说明。
- L2 知识文档的 contextId 在编程台里 = 这个项目，记这个仓库的事实（怎么跑、目录约定、踩过的坑），不和个人或主机的混在一起。

## 5. 不做的事

- 不做编辑器，不做补全、不做调试器。
- 不做远程项目（SSH 上的仓库）。
- 不做 LSP。
- 不去指挥 Cursor / Claude Code 等外部编程 agent。
- 编程工具不进普通助手、终端页、联络、关切。

## 7. 待讨论

1. **项目里改文件要不要确认？** 建议：宽松模式下，项目根内的改动不确认（有撤回兜底，也能在审改动里打回）；项目外照旧；删文件、改 `.git`、改项目外仍问。严格模式照旧全问。
2. **git 写操作谁来做？** 建议：agent 可以自己暂存、提交、开分支（按确认规则）；推送和强制类（`push`、`reset --hard`、改历史）一律问人，替我审批也不代批。
3. **同一个项目能不能同时开两个编程台？** 两个 agent 同时改一个仓库会互相踩，撤回也会乱。建议：允许开，但同一项目同一时刻只有一个在改（另一个只能看、或排队）。
4. **入口放哪？** 侧栏加一个固定的「编程」入口，还是在「新对话」里选项目时自动进编程台？
5. **编程会话进不进「最近对话」？** 建议进，和任务一起，但标出项目名；点开回到编程台。
6. **快照的边界**：超大仓库（几十万文件）或大量二进制时，快照怎么降级——只拍 agent 碰过的文件，还是直接提示「这个项目不支持撤回」？
7. **第一版支持哪些语言？** 自建引擎每种语言都要写一份「怎么认类、函数、调用」的提取规则。建议第一版 TypeScript / JavaScript、Python、Go、Java、C#、C / C++、Rust，其余只给大纲不给调用关系。
