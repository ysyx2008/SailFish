# 2026-10-26 每个伙计带自己的远程命令清单

已完成。分支 `feat/worker-remote-hosts`，接在运维专家之后。

## 要解决的事

一批只有一份命令清单，所有伙计共用：每个伙计在自己的每台主机上都能跑清单里的每一条。主机各不相同、要跑的命令也不同时：

- 只能把所有命令并成一份，每个伙计的权限比需要的宽；
- 确认卡上看不出「哪台跑哪条」。

## 做法

- 每个伙计（`tasks[]` 与 `batch.items[]`）可以带自己的 `remote_commands`；原有的整批 `remote_commands` 保留，作为所有带 hosts 的伙计共有的那份。伙计的清单 = 共有 + 自己的，去重。
- 授权按伙计生效：`RemoteGrant` 本来就是一个伙计一份，伙计只能跑自己那份。
- 确认卡：所有带 hosts 的伙计清单一样时，和现在完全一样（一份清单 + 分组主机）。不一样时按「清单相同的伙计」分块：每块写几个伙计、连哪些主机（按分组归好）、跑哪些命令。
- 运维专家看到同样的分块，按块判断。
- 命令行、IM 的确认文字同样分块。
- 补单不变：补给哪个伙计，就是那个伙计的清单。

## 取舍

- 不让秘书写「某台主机跑某条」的矩阵：伙计才是授权单位，一个伙计管的几台主机共用他那份清单。要让两台机器跑不同命令，派两个伙计。
- 错误：伙计写了 `remote_commands` 却没写 hosts、有 hosts 却没有任何命令（共有的也没有），整批退回并写明是哪一位。

## 改动范围

`packages/shared-types`（`RemoteAccessRequest` 增加分块）、`electron/services/agent/remote-access/`（授权门、专家的输入、纯文本描述）、`tools/sub-agent.ts`（解析与派出）、`tools.ts`（参数说明）、`src/components/ConfirmRemoteAccess.vue` 与 i18n、测试与 SPEC。

## 验收

- 单测：清单合并去重；分块只在清单不同时出现；伙计只能跑自己那份（别人的命令被拒）；各类错误回执。
- 端到端：本机假主机，两个伙计不同命令，各自只能跑自己的。
- 界面：卡上分块截图。
