# 2026-10-20 并行改动的验收实例与 `npm run review`

> 状态：未完成（等用户确认方案）

## 要解决的问题

用户同时开好几个智能体，每路在自己的工作树里改。规范已定为「做完交卷，用户验过说合才合」。要验，就得在合入前把那一路单独跑起来，但现在：

1. **分不清**：在工作树里跑 `npm run dev`，窗口和平时那个一模一样；Mac 上标题栏是隐藏的，写在标题里也看不见。
2. **抢数据**：两个实例都用同一份真实数据，同时读写会写乱；分支里带了数据迁移，切回来平时那个可能读不了。
3. **抢对外渠道**：两个实例都连同一个钉钉/飞书/企业微信机器人，消息可能被验收那个收走；关切、心跳、邮件、日历会各跑一遍，手机上重复收到提醒；网关端口冲突；`sailfish://` 深链接被抢。
4. **找不到**：Cursor 新开的终端停在对话所在目录，用户不会记得每路在哪棵树里。

## 设计目标（确认后升华进 SPEC / 规范）

- 用户只在主目录的终端里敲命令，用名字指定看哪一路，不用 `cd`、不用记路径。
- 主目录的 `npm run dev` 一点不变：永远是 `develop`、用真实数据、什么都照常连。
- 工作树里起来的一律是「验收实例」：
  - 一眼可辨：界面上常驻一个标记写着分支名；Dock 图标上有角标。
  - 用真实数据的副本：配置、AI 凭证、历史、知识库、技能、插件都在，用起来和平时一样；改坏了只坏副本。
  - 只给人看和点，不对外：不连 IM 机器人、不开网关、不跑关切/心跳/邮件/日历/定时任务、不注册深链接。界面里手动操作（含让 AI 干活）照常。
  - 可以和平时那个同时开着。
- 这一路合入或丢弃、工作树拆掉时，它的数据副本一起删。

**明确不做**：不做打包产物的预览（验收用开发模式就够）；不做多路同时合并的看板界面（`npm run review` 列表就是看板）；不改 GitHub 上的合并设置。

## 方案

### 1. `npm run review`（新脚本 `scripts/review.mjs`）

- **不带参数**：列出每一路，一行一条，人话：
  - 分支名、工作树位置
  - 比 `develop` 多几个提交、`develop` 已经往前走了几个提交
  - 没提交的改动有几处（有就醒目标出：「有 N 处没提交」）
  - 最后一次提交多久以前、标题
  - 智能体留下的状态说明（见下）
  - 已合进 `develop` 但树还没拆的，标「合完没拆」
- **状态说明的来源**：智能体交卷时把状态写进这条分支的 Git 分支描述（`branch.<名字>.description`，Git 自带、放在共用的仓库配置里，所有工作树都看得到），例如「等你验：xxx；验法：npm run review task-goal」。规范里加一条：交卷、改状态时同步写分支描述。
- **带名字**：`npm run review task-goal`，按分支名或工作树目录名的一部分匹配；匹配到多个就列出来让用户写得更具体。然后：
  1. 那棵树缺依赖就先跑 `.cursor/setup-worktree-unix.sh`。
  2. 这一路还没有数据副本就克隆一份（见下）；`--fresh` 重新克隆。
  3. 在那棵树里启动 `npm run dev`（输出直接接到当前终端，Ctrl+C 退出）。

### 2. 数据副本

- 来源：平时那个实例当前生效的数据目录（读同一个数据目录指针，用户迁过数据目录也跟得上）。
- 去处：`~/Library/Application Support/SailFish-review/<分支名转成的目录名>/`。
- 方式：APFS 写时复制克隆（`cp -c`），不带 `backups`、`knowledge-backups`、`knowledge-broken`、`logs`、`ai-debug-logs`、`Cache`、`Code Cache`、`GPUCache`、`Crashpad`、`cli-sandbox`、`config-backups`。粗估几十秒、几乎不占空间。
- 凭证能直接用：加密盐跟着数据目录走，种子在代码里，副本解得开。
- 已知局限：平时那个实例开着时克隆，正在写的文件可能拷到半截（例如知识库索引）。验收用够；真遇到了用 `--fresh` 重拷，或者先关掉平时那个再拷。

### 3. 认出「我在工作树里」并进入验收模式

- `vite.config.ts`：启动时比较 `git rev-parse --git-dir` 和 `--git-common-dir`，不同就是工作树。是工作树就：
  - 给 Electron 进程加环境变量 `SAILFISH_REVIEW_LANE=<分支名>` 和 `SAILFISH_REVIEW_DATA_DIR=<副本目录>`；
  - 副本不存在时直接报错退出，提示用 `npm run review <名字>` 起（避免悄悄用上真实数据）。
  - vite 端口本来就会自动顺延，不用改。
- `electron/utils/bootstrap.ts`：验收模式下最先 `app.setPath('userData', 副本目录)`，并跳过所有读写全局数据目录指针、迁移老目录、清理旧目录的步骤——那个指针是平时那个实例的，不能碰。
- `electron/main.ts`：验收模式下跳过
  - `setAsDefaultProtocolClient`
  - 定时任务、关切、传感器（心跳/邮件/日历/文件/探测）的启动，以及唤醒关切的补建
  - 网关自动启动
  - 各 IM 自动连接
  - 浏览器助手指针本来就是「先启动的占住」，平时那个开着时验收实例拿不到，不用改；平时那个没开时验收实例会占住，关掉后自动让出，可接受。
- 判断收在一个地方：新增一个很小的模块（例如 `electron/utils/review-lane.ts`）回答「是不是验收实例、分支名是什么、数据目录在哪」，各处只问它，不各自读环境变量。

### 4. 一眼可辨

- 主进程：`app.dock.setBadge('验收')`（Mac Dock 角标，切应用时也看得到）。
- 渲染进程：经 preload 暴露分支名；在主窗口顶部放一个常驻、不挡操作的小标记「验收中 · feat/xxx」，配醒目颜色。文案进 i18n（中英两套）。

### 5. 收尾

- 规范「收尾」一条补上：拆工作树时一并删 `SailFish-review/<分支>/`。
- `npm run review` 列表里，副本目录对应的分支已经不存在的，提示可以删（`npm run review --prune` 删掉）。
