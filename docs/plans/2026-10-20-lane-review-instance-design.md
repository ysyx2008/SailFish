# 2026-10-20 验收一路改动：`npm run review` 与验收标记

> 状态：未完成（已实现，等用户验收）

## 要解决的问题

用户同时开好几个智能体，每路在自己的工作树里改。规范已定为「做完交卷，用户验过说合才合」。要验，就得在合入前把那一路跑起来，但现在：

1. **找不到**：Cursor 新开的终端停在对话所在目录，用户不会记得每路在哪棵树里、走到哪一步。
2. **分不清**：在工作树里跑 `npm run dev`，窗口和平时那个一模一样；Mac 上标题栏是隐藏的，写在标题里也看不见。

## 设计目标

- 用户只在主目录的终端里敲命令，用名字指定看哪一路，不用 `cd`、不用记路径。
- 不带名字时列出每一路走到哪：智能体留下的状态、比 `develop` 多几个提交、`develop` 是否已经往前走、有没有没提交的改动、已经合完可以拆的。
- 工作树里起来的窗口一眼可辨：界面顶部常驻一个标记写着分支名；Dock 图标上有角标。
- **同一时间只开一个开发进程**（用户 2026-10-20 定）：验收时先关掉主目录那个，再起这一路。开多了容易搞混，也免得两个开发进程争同一份数据。验收那一路用的仍是平时那份真实数据。

**明确不做**（2026-10-20 用户说「不用这么复杂」后撤掉的）：不给验收实例复制一份数据；不在验收实例里关掉机器人、关切、网关、深链接；不支持两个开发进程同时开着。不做打包产物预览；不做看板界面（列表就是看板）；不改 GitHub 上的合并设置。

**已知局限**：

- 防呆只拦得住另一个开发进程，拦不住装好的旗鱼。装机版和开发版本来就共用一份数据（见想法本「开发版用独立数据目录」），这一点和以前在主目录跑 `npm run dev` 一样，没有变好也没有变坏。
- 分支里带数据迁移或改了数据格式时，验收会把真实数据迁过去，切回 `develop` 可能读不了。交卷时智能体必须点明，并建议先备份。

## 方案

### 1. `npm run review`（`scripts/review.mjs`）

- **不带参数**：列出主目录以外的每棵工作树，人话：分支、智能体写在分支描述里的状态、比 `develop` 多几个提交、`develop` 是否已经往前走、「提交都已经在 develop 里，可以拆了」/「刚开，还没有改动」、没提交的改动几处、游离 HEAD 警告、最后一次提交多久以前、位置、起它的命令。
- **状态来源**：智能体交卷、改状态时写 Git 分支描述（`git config branch.<名字>.description "…"`），共用仓库配置，所有工作树都看得到。
- **带名字**：先精确匹配分支名或工作树目录名，再按包含匹配；多个或没有就列候选、退出。然后：
  1. 5173 端口被占就拒绝，提示先关掉在跑的那个；
  2. 缺依赖先跑 `.cursor/setup-worktree-unix.sh`；
  3. 有没提交的改动就提醒一句；
  4. 在那棵树里启动 `npm run dev`，输出接到当前终端，Ctrl+C 一起退。

### 2. 只开一个开发进程

- `vite.config.ts`：开发服务器固定 5173、`strictPort`，第二个直接起不来，不再悄悄顺延到 5174。

### 3. 一眼可辨

- `scripts/review-lane.mjs` 的 `laneOf`：`git rev-parse --git-dir` 与 `--git-common-dir` 不同就是工作树，给出分支名。
- `vite.config.ts` 启动 Electron 前把分支名放进环境变量（变量名唯一定义在 `shared/review-lane.ts`），终端里打一行「验收：分支（位置）」。
- `electron/utils/review-lane.ts`：主进程唯一回答「是不是验收实例、分支名」，打包后恒为否。
- 主进程：Mac Dock 角标「验收」；IPC `app:getReviewLane`。
- 渲染进程：`ReviewLaneBadge.vue` 在主窗口顶部正中放一个琥珀色小标记「验收中 · 分支名」，悬停说明用的仍是平时那份数据。文案中英两套。

### 4. 规范

- 「跑起来验证」：智能体自己看界面仍用 `launchApp` + 临时数据目录，绝不起可见实例；用户验收用 `npm run review <名字>`。
- 交卷：写分支描述；消息里给出 `npm run review <名字>`；带数据迁移的要点明并建议备份。
- 架构文档常用命令补 `npm run review`。
