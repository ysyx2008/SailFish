# 团队产出物可见（2026-10-29）

已完成（2026-10-29），分支 `feat/agent-org`，待用户验收。用户明确要求先实现从组织图查看各团队成果，再盘点完善项。

## 方案

从主会话下的成员持久记录读取 CanvasData 文件成果和已交回的工作结果，以负责人和团名匹配成员；负责人本人的产出明确单列为共享成果，不归到任一团员。不扫描共享目录、不解析群消息里的路径。复用 CanvasData 与稳定产出物 ID；同一成果的更新合并。读接口只接受会话与团身份，不接受文件路径。旧记录无需迁移。

团框增加产出物入口，清单显示实际产出者、文件名与路径，提供空状态、失败重试、刷新。组织图内的成果清单复用既有 ArtifactPanel，以集合过滤页签并提供返回清单入口；助手暂停外层产出物预览，避免同一文件同时挂两个编辑器，终端/联络覆盖层同样能预览。铺满与返回保留当前查看习惯。成果归属不等于验收通过。

## 拆解与验收

1. 成果查询与 IPC：隔离临时成员记录验证同名团、更新、失败步骤、无成果与历史读取。
2. 组织图清单、产出物预览与返回：隔离 Electron UI 验证两个团不串、文件预览、铺满、返回及空状态。
3. 针对性单测、CLI 回归、界面端到端、自审和独立审查；只提交本任务，保留 feat/agent-org 待用户验收。

本批不修改恢复计数、层数口径、预算或成果保存期限。

## 本批范围与后续

当前展示成员记录中已登记的产出物及交回结果，负责人本人的成果共享单列。它不是目录文件管理器，也不证明文件作者或正式验收版本；未登记的任意 exec 文件不会从文本路径猜出来。

本批不修上一轮盘点的恢复人数重复、旧验收结论覆盖、新进程直叫深层成员、200 人/100 团展示截断、临时文件保存期限与预算治理。继续在既有验收分支追加提交，未合入；主线新增协作规则文档的同步留待合入前处理，避免改写已交验历史。

## 独立审查后追加修补（2026-10-29）

- 同一路径的协作编辑保留最早登记来源和分组，不因负责人或团员后来打开/修改而翻转；成果来源不等同文件作者或验收背书。
- 联络合并物理记录时逐条补原会话号，真实历史集成测试证明 A 的旧组织不会读到最新会话 B 的同名团成果。
- 组织步骤或会话切换清空旧清单并作废在途打开；收工和预览返回补读最新结果，避免最后一次轮询后漏成果。核对 SubAgentRoster 收尾顺序为归档结果、persistSlot、onProgress，成果状态先落盘再通知进度。
- 无定位键的更新按成员与 renderer 定位，标题不当定位键；后台轮询保留缺失文件错误，手动刷新清除；身份切换避免重复刷新。
- 成果查询异步读取 steps 并跳过 messages 全文。旧的完整记录读取默认行为不变；不改落盘格式。全会话状态目录读取、steps 缓存和大规模压测仍待后续，不宣称解决所有规模性能问题。
- 打开过的团队文件保留在本场产出物目录，沿用关闭页签不移出清单的既有习惯；退出组织图恢复进入前的主文档。界面端到端覆盖两项行为。
- 追加回归：44 个测试文件 437 项断言通过，组织 CLI 7 场景、基础 CLI 102 通过/3 跳过、真实界面端到端通过。类型检查仍仅报上述两处既有错误，ESLint 和 diff 检查通过。
- 扩大并行测试时 HTML 视口测试出现 jsdom teardown 的 `window is not defined` 输出；该模块本批未修改，单独运行其 10 项测试通过且未复现。保留为测试隔离限制，不将日志描述成完全无异常。
- 复核提出的非阻塞事项：大型记录进一步缓存/压测，以及有未保存草稿时的外部文件版本冲突提示还需更完整实测；不以本次预览可见代替版本化成果验收。
