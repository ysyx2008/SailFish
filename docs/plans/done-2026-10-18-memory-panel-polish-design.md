# 记忆栏目：别覆盖 AI 刚写的内容，列表看得出内容

状态：**已完成**（2026-10-18 落盘并实现）

设计目标已写入 `electron/services/knowledge/SPEC.md`「记忆栏目：编辑不覆盖 AI 刚写的、列表看得出内容」。本文只写怎么做。

## 要解决

1. 面板开着时 AI 仍在对话后更新记忆，面板只在手动点「刷新」时才重读；用户在旧文本上改完保存是整份覆盖，AI 期间写进去的会丢。
2. 列表每项只显示原文前 80 个字，常常是一串 markdown 标题符号，认不出内容，也看不出哪份快满。

## 做法

| 位置 | 改什么 |
|---|---|
| `electron/services/knowledge/context-knowledge.ts` | 给每份文档带「最后更新时间」（取文件修改时间，内存里随写入更新）；新增带「基准内容」的保存：保存时磁盘当前内容与基准不一致就拒绝并回报最新内容，不写盘 |
| `electron/main.ts`（`contextKnowledge:list` / `set`） | list 多返回更新时间；set 多收一个可选的基准内容，冲突时返回 `conflict` 与最新内容 |
| `electron/preload.ts`、`src/vite-env.d.ts` | 跟着补类型 |
| `src/components/Memory/MemoryPanel.vue` | ① 打开记忆页签、窗口重新获得焦点、以及停留时每 15 秒，在没有未保存改动时静默重读，选中的那份也跟着更新；② 保存带上打开时的内容，遇冲突弹确认：「这份记忆在你编辑期间被更新了」，可选「覆盖」「放弃我的修改并载入最新」「再想想」（关掉弹窗等于再想想，不动编辑区）；③ 列表项改成：标题 + 主题段标题（取各段的标题行，最多前几段）+ 字数/上限 + 更新时间 |
| `src/i18n/locales/{zh-CN,en-US}/`（knowledgeManager 域） | 新增冲突提示、更新时间、字数文案，中英同步 |
| 测试 | 服务：基准一致可写 / 不一致拒绝且不写盘 / 没带基准照旧；面板的主题段标题提取 |

## 任务拆解

1. ✅ 服务与 IPC：更新时间、带基准保存。验收：服务单测（冲突不写盘、没带基准照旧）。
2. ✅ 面板：自动刷新（有未保存改动不刷）、冲突确认。验收：手动在面板打开时用 CLI/另一路改记忆，面板不覆盖。
3. ✅ 列表：主题段标题 + 字数 + 更新时间。验收：真实数据下「用户」一项能读出主题。
4. ✅ 收尾：想法本。

## 不做

- 不加逐条来源标记；更新时间只到整份文档。
- 不做合并（冲突时只让用户二选一，不自动合并两份文本）。
- 编辑区折叠/大纲：用户定了先不动。

## 实现中补充（代码审查后）

- 文本框加字数上限，避免服务端截断后编辑区与存下的内容对不上而误报冲突。
- 保存期间用户继续输入的部分保持「未保存」；输入法组字时不自动刷新；正在看的那份在别处被删时，不再停在旧内容上。
