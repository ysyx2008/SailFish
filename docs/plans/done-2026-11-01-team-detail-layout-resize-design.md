# 团队画布位置稳定与详情调宽

日期：2026-11-01

状态：已完成，在 `feat/agent-org` 等用户验收，未合入。

## 问题与目标

当前数据顺序没有改变，问题是打开详情缩小了可视区，平面网格根据可视区宽度重新计算列数，数百个成员重新换行。选中成员虽在右侧显示，但原阅读位置失去意义。详情宽度目前也固定。

采用整个团队工作区的宽度计算画布布局，详情打开和调宽只改变可见范围；保留真实排序、布局坐标和垂直滚动位置，选中成员被遮住时仅作必要的最小滚动。真实窗口/工作区改宽仍允许自适应，不新增布局模式、用户设置或后端字段。

复用 `WorkbenchShell` 的拖动条、指针捕获和取消/卸载清理，不复制另一套拖拽实现。详情宽度有两侧边界，切换成员及关闭重开详情保留本次调宽；不记进持久配置。显式公开取消拖动和重新测量方法供团队宿主使用，其他宿主默认行为不变。团队内开合不使用挤压动画，减少视野漂移。

## 验证

- 500人平面团队，滚到中后段并点最右列成员：比较全部成员的顺序和逻辑坐标、垂直滚动位置；选中成员保持可见、详情对象正确。
- 拖大拖小详情，检验宽度上下界、画布坐标/缩放/垂直位置稳定、关闭重开保留宽度；屏外成员继续按视口绘制。
- Esc结束拖动而不关闭详情，失焦/卸载释放光标；再次关闭详情恢复总览。
- 真实界面回归覆盖成员、群聊、成果与返回；类型、构建和静态检查，较大交互改动独立审查，工具失败时结构化自审并披露。

## 实现与验证结果

- 布局使用完整工作区宽度，可视区独立用于缩放、绘制和最小滚动；详情开合、调宽都不改成员坐标。工作区本身改宽仍可自适应。
- 详情复用工作台分隔条，正常空间下左侧至少300px、右侧至少280px；很窄时各保留一半。关闭重开及切换对象保留本次调好的像素宽，不写配置。团队内禁用抽屉挤压动画，其他宿主原行为不变。
- `team-detail-resize.mjs`：深浅主题各18项，共36项。500人滚至约65%处的末列，打开详情后全部成员坐标、顺序和纵向滚动值不变；拖宽、收窄、边界、宽度保留、状态更新、Esc、失焦、pointercancel、窗口缩放及卸载释放均通过。成员资料来自临时目录，经真实历史IPC加载，不调用模型或使用用户业务数据。
- `unified-team.mjs` 50项、`organization.mjs` 145项、`team-performance.mjs` 30项均通过；覆盖成员、群聊、成果、逐层返回、千人/101小组完整可达及屏外内容回收。界面回归合计261项。
- 组织布局、视口及成果组件等35项单测通过；前端类型、Vite构建、改动组件ESLint和新脚本语法检查通过。

## 审查与限制

本机Claude CLI独立审查180秒没有返回任何输出，未取得独立结论，已终止该审查进程。结构化自审结论：

- 目标：所有卡片保持原顺序与逻辑坐标，可视区变化只触发视口绘制及必要的最小滚动，没有另做状态排序。
- 边界：像素宽按当前工作区限制，窗口缩小后不会将原请求宽永久覆盖；屏外卡片仍只保留槽位，不额外绘制全部内容。
- 失败路径：拖动先于分层关闭处理；失焦、pointercancel与卸载均清理指针捕获及全局光标/文本选择。区域宽度变更经公开方法测量，不读写子组件内部状态。
- 权限与数据兼容：仅前端布局，无新增权限、持久字段、用户设置、提示词或模型请求。
- 证据：以上隔离真实界面、组件回归及类型/构建均通过；jsdom只补齐ResizeObserver环境，不用它判断尺寸。

宽度只在本次团队界面中保留；退出整个团队后重新进入恢复默认宽。真实窗口或工作区本身改宽仍允许网格调整，详情开合和拖宽不触发换列。未进行真实500个模型请求的压力测试，本轮验证的是500人运行状态下的界面行为。
